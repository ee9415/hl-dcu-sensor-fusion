# 좌우 경계 독립 추적 및 가림 연결

작성일: 2026-10-21 | 소스/실행 개발 앱: 0.17.1

## 문제와 변경 근거

0.16.2는 피팅은 좌우 별도로 하면서도 초기 취득, 추정 만료, 도로 내부 검증과
표시 범위를 최종 경계 쌍에 묶었다. 한쪽이 가려지거나 관측 구간이 짧아지면
정상적으로 보이는 반대쪽까지 `LANE UNAVAILABLE`로 사라질 수 있었다.

사용자 요청에 따라 다음을 변경했다.

- 왼쪽/오른쪽에 관측 범위, 마지막 형상, 관측 시각, 원시 표식 연관 기준을 독립 저장.
- 한쪽만 처음 검출돼도 그쪽을 표시한다. 반대쪽은 과거 관측이 없으면 만들지 않는다.
- 가려진 쪽에만 이전 형상과 다른 쪽의 관측 변화량을 적용하여 점선으로 이어준다.
  설정 `max_lane_gap_s`(기본 2초)가 지나면 그쪽만 숨긴다. 보이는 쪽은 계속 추적.
- 양쪽의 도로 지지와 관측 범위를 따로 검증한다. 한쪽의 도로 마스크 충돌이나
  짧은 관측 범위 때문에 반대쪽 전체를 버리지 않는다. 둘의 표시 거리도 달라도 된다.
- 곡선 교차는 추정/약한 쪽의 충돌 범위만 제한한다. 정상 관측 측면은 유지한다.
- 출력 평활과 원시 표식 연관 기준을 분리하여, 재획득 때 평활된 선이 아직 먼
  위치에 있다는 이유로 실제 표식을 다시 놓치는 문제를 방지한다.
- 프레임 변화 제한은 공통 관측 범위에서 계산한다. 관측 밖 다항식 외삽 꼬리가
  실제 보이는 선의 반응을 과도하게 늦추지 않게 한다.
- 이전 경계가 새 가시 도로 밖으로 벗어나면 잘못된 위치를 평활 기준으로 고정하지
  않고 실제 관측 표식을 재취득한다. 이 경우 연속성보다 관측 정합을 우선한다.
- 중심선 계산·오버레이·목표점·선회 경로는 계속 제외한다.

차폭/여유 설정은 계속 최소 통과 폭 점검용이며 경계 간격을 강제하지 않는다.
RGB/객체/Depth/영상 녹화 및 전송 포트/식별자는 유지한다. 기존 중심선 알고리즘은
개발 이력으로 남기며 활성 후처리 노드는 이를 호출하지 않는다.

## 데이터 의미와 호환성

0.17.0에서 `boundary_valid`는 **한쪽 이상 유효**라는 뜻이다.

| 필드 | 의미 |
| --- | --- |
| `left_boundary_valid` / `right_boundary_valid` | 각 측면의 출력 유효성 |
| `boundary_pair_valid` | 공통 전방 표본이 충분하며 순서가 올바른 좌우 쌍 |
| `left_boundary_state` / `right_boundary_state` | observed / inferred / held / unavailable |
| `boundary_state=partial` | 한쪽만 표시 가능한 상태 |
| 좌우 좌표 배열의 `null` | 해당 측면 미관측/만료 또는 그쪽 표시 범위 밖 |
| 빈 폭/clearance | 좌우 공통 범위가 부족해 폭 판단 불가능 |

좌우 좌표 배열 길이는 공통 `boundary_forward_dev` 길이와 같고, 각 표본의 null은
NaN/0으로 변환하지 않는다. 양쪽 다 무효면 기존처럼 좌표 배열은 `[]`이다.
TCP JSON에는 NaN/Infinity를 송신하지 않는다. CSV는 이 null 좌표를 JSON 배열로
저장하며, 폭/여유 미확정 값은 빈 셀이다. `boundary_pair_valid=False`가 항상
한쪽 무효를 뜻하지는 않는다. 둘 다 보여도 전방 범위가 충분히 겹치지 않을 수 있다.

BEV는 미보정 개발 좌표이므로 거리·여유 판정을 실차 통과 가능 판단에 쓰지 않는다.
가림이 길어지면 추정 쪽은 표시가 중단된다. 보이는 쪽도 NN/RGB 오검출, 그림자,
주차칸/노면 글자 혼동으로 놓칠 수 있다. 차량 운동 보상·교차로 출구 선택은 미구현.

## 0.17.0 호스트 검증

Windows 번들 Python/NumPy에서 전체 77개 테스트 통과. 이후 강화한 TCP CSV
부분 좌표/null·좌우 유효성 검사도 별도 통과했다.

- 처음부터 왼쪽만/오른쪽만 입력: 해당 색상 경계만 표시, 반대쪽 null.
- 양쪽 관측 후 각 측면 가림: 초기 추정 동안 마지막 관측 폭 분포 유지.
- 2초 가림 만료 후에도 관측 측면은 유효/observed 유지.
- 서로 다른 좌우 관측 범위를 합쳐 표시하며 각 측면의 범위 밖은 null.
- 가려진 쪽의 도로 마스크 충돌이 보이는 쪽을 지우지 않음.
- 호스트 후처리 통합: 한쪽 입력에도 결과/BEV 생성 및 단일 경계/중심선 제외 확인.
- JSON 엄격 직렬화 및 CSV의 부분 유효성·null·빈 여유값 저장 확인.
- 기존 차선/급확장/곡선/시간 역순/Depth/객체/telemetry 회귀 포함.

Serena는 다른 프로젝트 루트를 가리켜 이 저장소 파일 접근을 거부했으므로 일반
파일 도구를 사용했다. 루프백 통신은 샌드박스 밖에서 검사했다. ROS2 경로가
아니므로 colcon/topic/TF 검증은 해당하지 않는다.

## 최종 0.17.1 외삽 제한과 배포 (2026-10-21)

보이는 쪽이 짧게 관측될 때 그 다항식의 관측 밖 꼬리를 가려진 쪽 전체에
복사하지 않도록 수정했다. 실제 관측 변화만 거리 범위 안에서 사용하며, 밖에서는
끝점 이동을 이어간다. 프레임별 최대 이동량으로 제한하므로 가려진 긴 경계가
외삽으로 급변하지 않는다. 이 합성 사례를 추가한 전체 78개 테스트가 통과했다.

0.17.1 카메라 개발 앱 재배포 후 동일 멀티뷰 자동 재연결을 확인했다.
재시작 직후 첫 별도 수신 검사는 준비 전 포트 접속으로 실패했으며, 포트 준비 후
재검사 결과와 최종 표본은 아래에 추가 기록한다. 사용자 영상/CSV는 계속 Git 제외.


최종 버전 `OAKAGENT_APP_VERSION=0.17.1`, 영상/데이터 포트 5개 열림 확인.
최종 `lane_boundaries.py` LF SHA256은
`f1897929147abaa5b3de4f8ed241b1ed7cc518d995dea31d843d3f88e577327b`이며
로컬 소스와 일치한다. 후처리 노드 파일은 0.17.0과 동일하다.

최종 세션 `bc1a1e10-1c80-44ad-bec7-7f7e7a51ff54`의 초반 403프레임에서
왼쪽만 유효 1, 오른쪽만 유효 55를 확인했다. 상태는 양관측 209,
좌관측/우추정 4, 좌추정/우관측 5, 양추정 14, 좌미검출/우관측 29,
좌미검출/우추정 26, 좌관측/우미검출 1, 양미검출 115다.
이 세션 표본의 중심선 true/계수/시퀀스 누락은 모두 0이었다.
모니터 영상에 표식 없는 교차로 구간이 포함되며, 그곳에서는 여전히 양쪽 표시가
없을 수 있다. 한쪽 근거만 남을 때 반대쪽 때문에 같이 사라지는 문제와는 구분한다.

최종 고정 집계는 `artifacts/independent_boundaries_0171/metrics.json`.
포트 준비 후 직접 수신 재검사 산출물은
`artifacts/independent_boundaries_0171/streams_ready/`에 기록했다.
멀티뷰는 정상 연결 및 CSV 증가를 확인한 상태로 유지했다. GUI의 누적 건수/누락은
재시작 이전 여러 세션도 포함하므로 위 최종 세션 표본의 누락 0과 혼동하지 않는다.
