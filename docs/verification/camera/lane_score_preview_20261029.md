# 차선 점수 임계값·RGB 오버레이 미리보기 (2026-10-29)

## 참고 이미지 기반 표시 옵션 (동일 날짜 후속)

사용자가 제시한 원본/검정 배경 점수 구간색/RGB 구간색 겹침 예시에 맞춰
미리보기 선택지를 확장했다. 인식 계산과는 별개인 표시 옵션이다.

| 멀티뷰 선택 | 내용 |
|---|---|
| 일반 인식 결과 | 기존 마스크·객체·경계·추종선 |
| 원본 RGB | 같은 입력 프레임의 RGB만 표시(프레임 번호 포함) |
| 점수 구간색 (검정 배경) | 선택된 차선 점수 픽셀의 구간색, 나머지는 검정 |
| 원본 + 구간색 겹침 | RGB 위에 같은 구간색 픽셀 합성 |
| 원본·구간색·겹침 3분할 | 동일 callback의 세 화면을 한 결과 스트림에 비교 |
| 차선 점수 RGB | 기존 픽셀별 연속 무지개색(낮음 보라→높음 빨강) |
| 임계값 마스크 RGB | 기존 하늘색 단색 마스크 |

참고 구간색은 기존 연속색과 방향이 반대다. 낮은 점수0.05부터 빨강,
주황, 노랑, 연두, 초록, 청록, 하늘색, 파랑 계열을 거쳐 높은 점수0.95는
보라로 표시한다. 실제 구간 하한은 0.05/0.15/0.25/0.35/0.45/0.55/
0.65/0.75/0.85/0.95이며 경계값은 상위 구간에 포함한다. 0.05 미만은
검정 배경에서는 검정, RGB 겹침에서는 원본 그대로다. 원시 점수는 정답
확률로 보정한 값이 아니며 구간색도 실제 정확도를 의미하지 않는다.

새 구간색 계열로 처음 전환하면 UI 임계값을0.05로 설정해 약한 픽셀도
비교하게 한다. 구간색 계열 사이에서는 사용자가 바꾼 임계값을 유지한다.
슬라이더를 올리면 해당 점수 미만을 숨기며, 최소 표시 점수는 항상0.05다.
원본RGB에서는 표시 임계값을 사용하지 않는다. 기본 미리보기는 여전히
일반 인식 결과다.

구간색 단독/겹침 화면에는 오른쪽 세로 범례(최저 `<0.05` 포함)를 표시하고
현재 임계값 구간을 흰 테두리로 표시한다. 3분할은 960x540 캔버스에 같은
프레임의320x180 세 패널을 나란히 놓고 공통 하단 범례를 쓴다. 추가 추론이나
추가 RTSP 스트림을 만들지 않는다. 전체 후처리 계산은 그대로 수행한다.

이 옵션 추가 직전 카메라로 복원:


전체190개 회귀 검사 및 실제Tk의 전 모드왕복/실패복원, 구간색 계열 첫

## 사용자 확인: 차선 마스크 픽셀만 개별 원시 점수색 (동일 날짜 후속)

사용자는 전체 영상 열화상이 아니라, RGB 배경을 유지하고 **차선 마스크에
선택된 픽셀 각각을 자기 점수에 맞게 칠하는 형태**를 개념 이미지로 확인했다.
열화상 화면 추가는 취소했으며 해당 모드는 구현/배포하지 않았다.

최신 `차선 점수 RGB`는 다음과 같이 동작한다.

- 선택 임계값 이상의 차선 픽셀만 무지개색으로 표시한다. 임계값 미만 RGB
  픽셀은 오버레이 함수에서 바이트 단위로 유지한다(문자·색상표 영역 제외).
- 차선 하나의 평균/대표색을 쓰지 않고 원시 점수 각각에 직접 색을 대응한다.
- 기존의 넓은7구간 단색을 연속색으로 바꿔 같은 구간 안의 점수 차이도
  표현한다. 보라0.0, 파랑0.20, 청록0.35, 초록0.50, 노랑0.65,
  주황0.80, 빨강1.0을 기준으로 채널별 선형 보간한다.
- 선택 픽셀의 합성 강도는0.8로 고정한다. 같은 점수의 픽셀은 임계값을
  바꿔도 계속 선택되는 동안 같은 합성색이다. 임계값은 마스크 선택만 바꾼다.
- 원시 모델 해상도에서 픽셀별 색을 만든 뒤 정수배 최근접 확대한다. 이웃
  점수를 평균하거나 모양만 예쁘게 보이게 색을 임의로 섞지 않는다.
- 실제 점수가0.99~1.0에 몰리면 빨강이 많다. 확인용 생성 이미지는 다양한
  점수를 가정한 개념도였으며 실제 모델의 분포를 뜻하지 않는다.

기존 `임계값 마스크 RGB`는 단색 마스크로 유지한다. 픽셀별 색을 보려면
`차선 점수 RGB`를 선택한다. 기존 인식용0.50·마스크 출력·경계/추종선
계산에는 영향을 주지 않는다. 아래의 이전 구간색/미만 약한 표시 설명보다
이 픽셀별 선택·연속색 정의가 최신이다.

원상 복원:

```powershell
python src/hl_camera_bringup/scripts/manage_virtual_guidance.py rollback --device-ip 192.168.201.2 --backup artifacts/lane_pixel_score_20261029/device_before
```

호스트 원본은 `artifacts/lane_pixel_score_20261029/host_before/`에 보존했다.
전체186개 회귀 검사 통과. 실제 카메라 고정입력235프레임에서 인식용
마스크2045픽셀이 동일했고, 점수별 화면4장과 점수범위0~1·오류0을

## 무지개 구간색 보완 (동일 날짜 후속)

사용자 요청으로 `차선 점수 RGB`의 단순 파랑-초록-빨강 연속색을 고정
7개 점수 구간색으로 바꿨다. 마스크 단색 화면과 인식 임계값은 유지한다.

| 점수 구간 | 색 |
|---|---|
| 0.00 이상 0.20 미만 | 보라 |
| 0.20 이상 0.35 미만 | 파랑 |
| 0.35 이상 0.50 미만 | 청록 |
| 0.50 이상 0.65 미만 | 초록 |
| 0.65 이상 0.80 미만 | 노랑 |

수치와 선택 임계값의 흰색 표식을 표시한다. 프레임마다 최소·최대로 색을

강조 밝기를 바꾸며, 미만인 점수도 약하게 남긴다. 높은 점수만 많은 장면은

## 사용자 선택과 동작

사용자는 임계값을 기존 인식·경계·추종선 처리에 적용하지 않고 **미리보기에만
적용**하기로 선택했다. 기존 차선 인식 임계값 0.50과 모델은 유지한다.

멀티뷰 소스 제어부의 `YOLO 결과 화면`에서 다음을 선택한다.

- 일반 인식 결과: 기존 마스크/객체/경계/추종선 화면.
- 차선 점수 RGB: 원시 차선 점수의 연속 색상과 RGB를 합성한다.
  낮은 점수 파랑→중간 초록→높은 점수 빨강이며 고정 0~1 색상 눈금을 쓴다.
  선택 임계값 미만도 약하게 표시하고 이상인 픽셀을 더 밝게 표시한다.
- 임계값 마스크 RGB: 선택 임계값 이상인 픽셀만 하늘색으로 RGB에 합성한다.

임계값은 0~1, 기본0.50이다. 슬라이더를 놓거나 숫자 입력 후 Enter/적용으로
전송한다. 화면에 PREVIEW ONLY, 선택 임계값, 선택 면적 비율,
인식 기준 BASE 0.50을 표시한다. 점수 화면 하단의 흰색 표식이 선택 임계값이다.
0을 선택하면 점수0인 픽셀도 포함된다.

새 스트림을 추가하지 않고 기존 YOLO 결과 RTSP(8554/yolopv2)의 화면을
전환한다. 원본 RGB/Depth/BEV 스트림과 기존 녹화 대상 선택은 유지한다.
YOLO 결과를 녹화 중이면 선택한 미리보기 화면도 해당 MP4에 기록된다.
기본/전체 후처리 모두에서 미리보기가 동작하며, 전체 후처리 계산은 화면에
보이지 않아도 원래대로 수행된다. 멀티뷰 재시작 후 새 제어부가 나타난다.

## 계산·프레임 정렬

`lane_overlay.py`에서 원시 차선 tensor(NCHW 또는 NHWC)의 레터박스를 제거해
320x180 점수 맵을 얻는다. 같은 후처리 callback의 RGB와 합성하므로 별개
스트림의 프레임을 임의로 맞추지 않는다. 320x320 및 320x192 레터박스와
텐서 배치를 검사한다. 실제 운용 모델은 기존320x320을 유지했다.

미리보기 전용 `lane_overlay` 제어 명령은 mode와 threshold를 검증하고,
소스/처리 세대 및 추적 이력을 초기화하지 않는다. 기존 segmentation_masks,
마스크 노드 출력과 경계·추종선 입력은 그대로다. 원시 출력이 기대 점수 범위를
벗어나거나 비정상이면 logits를 임의 변환하지 않고 기존 화면으로 돌아가며
LANE SCORE UNAVAILABLE을 표시한다. 인식 처리는 계속한다.

이 점수는 모델 출력이며 실제 정답 확률로 보정한 값이 아니다. 높은 점수를
가진 잘못된 도로 표식은 임계값을 올려도 남을 수 있다. 미리보기 오버레이는
추가 렌더링 비용이 있으므로 처리 속도 향상을 의미하지 않는다.
