- 카메라 6대 정보·장치 ID·선택·SDK 경로, 마지막 적용한 영상 입력 설정을 저장한다.
- 표시 설정(후처리 모드·경계선 표시·차선 색상 모드·임계값), 메인 녹화 영상 선택,

- 표시 설정은 장치 적용 성공 시, 6대 녹화 설정은 확인 시 저장한다. 정상 종료 시에도 카메라·표시·녹화 선택을 저장한다.

- 기존 `--camera-settings` 또는 `OAK_CAMERA_SETTINGS_PATH` 지정 시 비밀번호를 포함해 해당 경로의 **한 파일**에 설정을 모은다.
- 복원 자체가 카메라 앱·PC 전송·녹화를 자동 시작하지 않는다. `--auto-connect`는 기존 동작을 유지한다.
- 검증: `artifacts/unified_settings_20261103/verify.py` 실제 Tk 재실행 및 DPAPI 왕복,
  카메라 초기화 시 다른 섹션 유지, 자동 전송 없음. 변경 전 코드는 같은 폴더 `backup`에 보관했다.

## 사용

- `6대 카메라 녹화 → 카메라 설정 → 카메라 정보 저장`으로 저장한다.
- 카메라 설정의 `확인`, 검색 결과 `설정에 적용`, 연결 및 녹화 시작에서도 저장한다.
- 다음 실행 시6대의 IP/장치ID/입력 종류/녹화 선택과 OAK-D Python 경로를 읽는다.
  장비 연결이나 녹화를 새로 자동 시작하지는 않는다. 기존 `--auto-connect`는 유지된다.
- 카메라 설정의 `카메라 정보 초기화`는 확인 후 등록 정보를 빈 값/기본값으로 저장한다.
  녹화 중에는 거부한다. 현재 영상 수신 연결, 녹화 파일, 기존 백업, 장치 자체의 네트워크
  설정은 변경하지 않는다. 초기화 후 새 연결/녹화 전에는 다시 등록해야 한다.
- 빈 초기화 프로필을 남기므로 다음 실행에 오래된 로그에서 정보가 다시 채워지지 않는다.

## 저장 파일과 우선순위

기본 파일: `artifacts/config/cameras.json`. 프로젝트 경로가 Windows와 WSL에서 같으므로
동일한 파일을 사용한다. 비밀번호는 저장하지 않는다. 녹화 출력/FPS 등은 이번 저장 대상이 아니다.
OAK-D Python 경로가 현재 OS에서 없으면 기존 런타임 기본값을 사용한다.

원자 교체로 저장하며, 변경 전 파일은 `cameras.json.bak`에 보관한다. 같은 내용을 다시 저장할
때는 이전 백업을 덮어쓰지 않는다. 잘못된 형식/중복 IP·ID는 저장을 거부하며,
손상된 파일을 불러오지 못하면 상태를 표시하고 자동으로 덮어쓰지 않는다.

기본 실행은 저장한 CAM01을 메인 인식 탭에도 사용한다. 실행 명령에서 `--device-ip` 또는
`--device-serial`을 명시하면 그 실행 인자가 CAM01 저장값보다 우선한다. 저장값을 쓰려면:

```cmd
wsl.exe -d Ubuntu-22.04 -- bash /mnt/d/git_hub/hl-dcu-sensor-fusion/tools/run_oak_recorder.sh --auto-connect
```

다른 프로필은 `--camera-settings <JSON경로>` 또는 `OAK_CAMERA_SETTINGS_PATH` 환경변수로
지정한다. 명시한 새 경로에서는 녹화 로그 자동 이관을 실행하지 않는다.

## 검증

### 영상 입력 소스 기억

- `소스 적용` 시 입력 종류(카메라/PC 영상 파일), 파일 경로, 반복 재생, 시작/종료 구간,
  전송 FPS를 카메라 프로필 옆 `video_input.json`에 원자적으로 저장한다.
- 다음 실행 시 입력란과 PC 전송용 적용 설정을 복원한다. 장치 입력 전환이나 PC 전송은
  복원만으로 자동 시작하지 않는다. 카메라는 연결 후 `소스 적용`, PC는 연결 후 `전송 시작`한다.
- 저장 파일이 손상됐으면 기본값을 유지하고 안내한다. 영상 파일이 없으면 경로를 복원하되
  PC 전송 설정은 활성화하지 않고 파일을 다시 선택하도록 안내한다. 카메라 정보 초기화와는 별도다.
- 변경 전 코드는 `artifacts/video_input_settings_20261103/backup/oak_recorder.py`에 보관했다.
  같은 폴더 `verify.py`에서 실제 Tk 재실행, 6개 항목 복원, 자동 전송 없음, 카메라/PC 전환,
  파일 누락/손상 및 저장 실패 시 기존 파일 보존을 검증했다.

### 인식·검증 탭 연결 정보와 카메라 제어 추가

- 오른쪽 상단 `카메라 상태 확인`: 입력 IP의 oakctl 앱 목록에서 프로젝트 YOLOPv2 앱의 상태를 확인한다.
  확인 결과 실행 중은 녹색 LED, 멈춤/미설치는 적색, 통신 실패/미확인은 회색으로 표시한다.
  5초 주기로 자동 조회도 한다. LED는 앱 프로세스 상태이며 영상 내용 정상 여부를 판정하지 않는다.
- `카메라 앱 실행`: 실행 중이면 알림만 표시한다. 멈춰 있거나 미설치일 때만 로컬
  `apps/yolopv2_standalone` 경로로 `oakctl app run ... --detach -d <입력 IP>`를 실행한다.
- `앱 실행 멈춤`: 해당 프로젝트 앱만 중지하고 상태를 재조회한다. 다른 장치 앱에는 명령을 보내지 않는다.
  녹화 중에는 녹화를 먼저 끝내도록 안내한다. 중지 후 영상 수신은 자동 재접속 대기 상태가 된다.
- 일반 `영상 연결`과 자동 연결은 기존 동작을 유지한다. 앱 제어는 비동기 실행하며 중복 명령을 막는다.
- 장비 연결 팝업 `IP·비밀번호 저장`: IP는 기존 카메라 프로필에, 비밀번호는 IP별로 암호화 저장한다.
  비밀번호 입력란은 저장 후 비우며, 다음 연결에서 빈칸이면 저장된 값을 사용한다.
- Windows는 기존 DPAPI, WSL은 Windows PowerShell을 통해 동일한 사용자 범위 DPAPI를 사용한다.
  WSL 암호문 파일은 `artifacts/config/credentials.json`이다. 평문 파일 저장은 하지 않는다.
  일반 Linux에서는 Windows 암호화 저장소를 사용할 수 없으므로 저장 오류를 표시한다.
- IP 초기화는 비밀번호 저장소를 삭제하지 않는다. 저장소의 암호문은 해당 Windows 사용자만 복호화한다.
- 수정 전 멀티뷰 파일은 `artifacts/camera_controls_20261103/backup/oak_recorder.py`에 보관했다.
- `artifacts/camera_controls_20261103/verify.py`: 실제 WSL→Windows DPAPI 왕복, IP별 저장/복원,
  손상 파일 처리, Tk 저장 버튼 및 오프라인 상태 표시를 검증했다. 실장치 앱 실행은 하지 않았다.
- 분리한 앱 제어 검증: `artifacts/camera_app_restart_20261103/verify_controls.py`에서 가상 상태로
  이미 실행 중이면 재실행하지 않음, 멈춤에서 실행, 대상 앱 중지, LED 녹색/적색/회색,
  녹화 중 중지 방지를 확인했다. 변경 전 PC 코드는 같은 폴더 `backup/oak_recorder.py`에 보관했다.
