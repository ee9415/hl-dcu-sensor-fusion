멀티뷰 소스 제어부에 `차선·가상 경계선 표시` 체크박스를 추가했다.

## 추종선 연속 표시 (동일 날짜 후속)

사용자 요청으로 경로가 현재 마스크 검증을 통과하지 못할 때도 표시용 추종선을
유지한다. 가상 경계의 중간 형상과 차량 중앙 대리점에서 표시용 단일 2차
곡선을 계산하고, 현재 영역이 없으면 마지막 곡선을 유지한다. 경계와 표시
추종선에 공통 혼합 비율 및 40px/s 제한을 적용한다. 유효 경로로 복귀할 때도
직전 표시 곡선에서 이어가도록 했다.

유효 경로는 밝은 하늘색 실선, 현재 검증되지 않은 표시용 추정선은 어두운
하늘색 점선과 `PATH ESTIMATED`로 구분한다. `guidance_valid=False`인
프레임에서 기존 유효 경로 필드 `guidance_path_image/target/coefficients`는
계속 비어 있고, 새 `guidance_display_path_image` 및
`guidance_path_display_available/state`에 표시용 곡선을 기록한다.
따라서 표시 유지가 차량 제어에 사용할 경로의 유효성을 뜻하지 않는다.

입력/모드/시각 초기화로 다른 장면이 되면 표시 이력도 초기화한다. 처음부터
주행 가능 영역과 이전 경계 모두 없으면 근거 없이 임의 경로를 만들지 않는다.

저장 영상 50프레임에서 경계와 추종선 모두 50/50 표시됐다. 경로 현재 검증은
47/50으로 그대로이며 나머지 3개에도 표시용 추정선을 제공한다. 화면 표시
지속성과 실제 경로 정확도를 구분한다.
전체175개 회귀 검사 통과. 마스크 단절 시 마지막 추종선 유지, 도로 기반
표시 추정선 초기화, 단일2차 함수, 경계 중간점 종점, 복귀 시 변화율과
소스 전환 시 이력 초기화를 검사했다.

배포 후 PC 도로 60~76초 구간 25초 장치 시험에서 251프레임 모두 경계와
추종선이 표시됐다. 현재 검증 경로 186, 표시 추정선 65프레임이다. 표시
추종선 최대 변화20.835px/s(상한40), 경계40px/s, 상한 위반0. 표시곡선
2차 함수 오차 최대5.2e-13px, 경계 중간점 종점 오차1.5e-13px 이내다.
발행9.142FPS, 10FPS 요청, 결과영상 수신을 포함한 단일 단기 시험으로
장시간10FPS나 정답 경로 정확도 검증은 아니다. 모델/전처리/원래 추적기를
유지했고 시험 후 카메라 입력/full 모드로 복귀했다.

이번 수정 직전 카메라 상태로 롤백:

```powershell
python src/hl_camera_bringup/scripts/manage_virtual_guidance.py rollback --device-ip 192.168.201.2 --backup artifacts/guidance_path_persistence_20261028/device_before
```

호스트 원본은 같은 폴더의 `host_before/`, 검증 자료는
`artifacts/guidance_path_persistence_20261028/`에 보존한다.

## 가상 경계 사라짐 수정 (동일 날짜 후속)

사용자가 가상 경계가 사라지는 현상을 보고했다. 첫 구현은 `invalid()`에서
경계와 경로를 함께 비우고 `draw_guidance()`도 path valid일 때만 모든 선을
그렸다. 앞선 256프레임 장치 검사에서 경로 무효 49프레임이 그대로 경계
미표시로 이어지는 설계였다. 경로의 보수적 무효 처리가 경계의 연속 표시를
막았으므로 요구에 맞게 분리했다.

현재 구현에서는 경로가 무효여도 다음 순서로 경계를 표시한다.

1. 현재 연결된 주행 가능 영역에 맞는 매끄러운 가상 좌우 경계를 재구성한다.
2. 현재 영역으로 재구성하기 어려우면 이전 경계를 이동 없이 유지 추정한다.
3. 새 영역으로 전환할 때도 경계의 40px/s 변화 상한을 적용한다.

현재 영역의 검증을 통과하지 않은 유지/전환 경계는 어두운 주황색 점선과
`BND HELD UNVERIFIED` 또는 `BND TRANSITION UNVERIFIED`로 표시한다.
실제 관측이나 유효 주행경로로 취급하지 않는다. 해당 프레임의
`guidance_valid=False`, path/target/coefficients는 비어 있다.
`guidance_boundaries_available`, `guidance_boundary_state`,
`guidance_boundary_road_supported`로 경계 표시와 경로 유효성을 구분한다.
현재 영역으로 만든 경계만 있는 경우 `BND ROAD FALLBACK`이다.

처음부터 유효 영역도 이전 경계도 없는 장면에서는 근거 없는 선을 새로
만들지 않는다. 입력 소스/처리 모드/시각 불연속으로 추적이 초기화될 때도
다른 장면의 이전 경계를 넘기지 않는다. 따라서 차선 부재를 보완하는 것과
주행 가능 영역 및 모든 이력이 없는 상태는 구분한다.

이 수정 뒤 저장된 도로 마스크 50프레임에서 경계 표시 50/50, 유효 경로
47/50(road_fallback 2, transition_unverified 1)이었다. 전체 171개 검사 통과.
정답 정확도나 모든 도로에서의 연속 표시 보장은 아니다.

실제 장치에서 PC 도로 영상 60~76초를 10 FPS 요청으로 25초 재생했다.
253프레임 모두 경계 표시가 있었다. 유효 경로 189, 현재 도로 기준 가상
경계만 표시 5, 현재 영역 검증을 통과하지 않은 전환 추정 59프레임이다.
연속 경계 250쌍과 유효 경로 176쌍에서 40px/s 상한 위반 0, 저신뢰 실제
기준 사용 0, 시퀀스 불일치/처리 오류 0. 발행 9.184 FPS이며 결과 RTSP도
시험 중 추가 수신했다. 이전 시험과 엄밀한 동일 부하 A/B가 아니며 10 FPS
달성이나 정답 정확도를 의미하지 않는다. 원자료는
`artifacts/guidance_persistence_20261028/device_replay/`.

후속 배포 전 장치 전체 앱 소스가 앞선 수동 파일 배포 상태와 달라졌음을
확인했다. 현재 장치의 main/postprocess/추적기를 다시 백업한 뒤 그대로
보존하고 새 node/guidance/설정만 배포했다. 이 수정 직전 상태로 복원하려면:

```powershell

```

로컬 수정 전 파일은 `artifacts/guidance_persistence_20261028/host_before/`,
현재 도로 재생 산출물은 `artifacts/guidance_persistence_20261028/`에 있다.
이전 절의 최초 배포 원본 백업도 보존했다. 후속 배포 후에는 이전 백업 도구의
덮어쓰기 방지 검사에 걸릴 수 있으므로 우선 위 후속 백업으로 복원해야 한다.

## 범위와 좌표

사용자 요청으로 기존 중심선 제외 방침과 별개인 가상 주행경로를 추가했다.
320x320 모델과 기존 마스크·객체·경계 추적·정지선 계산은 유지한다.
차량 제어 연결이나 실전 출력 API 변경은 하지 않았다. 앞차 없는 단독 차량
시험을 전제로 한 영상 좌표 디버그 기능이며, 실제 거리와 조향 가능성을
검증한 경로가 아니다.

`virtual_guidance.py`가 기존 `ImageBoundaryTracker`의 결과와 320x180
주행 가능 마스크를 받아 별도 결과를 만든다. 기존 추적기에 가상 경계나
경로를 되먹이지 않는다. 후처리 full 모드에서 동작하고 basic에서는 우회한다.

## 경계 선택과 종점

- 현재 `observed`, 신뢰도 >=0.55, 실제 지원점 8개 이상 및 세로 범위
  16px 이상, 복원된 쌍이 아닌 경계만 실제 기준 후보로 사용한다.
- 3프레임 연속 일관된 관측 후 실제 기준으로 재채택한다. 낮은 신뢰도의
  새 좌표는 즉시 제외한다. held/predicted/inferred/aligning은 실제 기준이 아니다.
- 관측점으로 재적합한 경계가 현재 연결된 주행 가능 구간에서 크게 벗어나면
  실제 기준으로 사용하지 않는다. 페인트 마스크 제외를 고려한 여유는 8px이다.
- 양쪽 실제 기준이면 양쪽을 사용한다. 한쪽이면 반대쪽을 가상으로 보완한다.
  폭은 신뢰 가능한 양쪽 관측에서만 학습하며, 없으면 현재 도로 폭의 80%를
  시험 초기값으로 사용한다. 폭은 미터가 아니며 반대편 공간이 좁으면 하나의
  다항식 배율로 줄인다. 이 값은 확정된 실전 차폭 정책이 아니다.
- 양쪽 기준이 없으면 차량 앞에 연결된 주행 가능 구간의 가장자리를 매끄러운
  다항식 경계로 구성한다. 작은 요철을 점별로 따라가지 않는다.
- 기본 종점 높이는 영상 50%(320x180에서 y=90). 연결된 구간이 없거나
  너무 좁으면 아래쪽 75%까지 탐색한다. 분리된 영역을 평균하지 않는다.
- 양쪽 기준이 없으면 해당 높이의 실제 주행 가능 구간 중간점을 목표로 한다.
  실제/가상 경계와 경로를 동일 비율로 안정화하므로 전환 중 표시 종점은
  원시 마스크 중간점으로 즉시 점프하지 않는다.
- 유효한 아래쪽 대체 높이는 소스/모드 리셋까지 유지해 마스크 한두 행 변화로
  종점이 반복해서 사라지지 않게 했다. 현재 높이가 무효면 재선택한다.

## 2차 곡선과 안정화

시작점은 `(319*0.5,179*0.995)`인 영상 하단 중앙 대리점이다. 실제 차량
중앙의 투영을 측정한 값은 아니며 설치에 맞춰 설정 가능하다.

`t=(시작 y-y)/(시작 y-종점 y)`에 대해
`x(t)=시작 x+(종점 x-시작 x-k)*t+k*t²`를 사용한다.
`k`는 좌우 기준 곡선의 중간 형상에서 얻고, 출발점 근처에서 반대 방향으로
돌아 나가지 않도록 제한한다. 차량 진행 방향이나 조향 조건을 강제하지 않는다.
S자나 점별 클리핑을 사용하지 않는다. 텔레메트리 계수는
`x=c0+c1*y+c2*y²`이고 유효 y 구간은 path 좌표에 들어 있다.

좌우 경계와 경로의 다항식 계수를 공통 비율로 혼합해 종점이 두 경계의
중간점이라는 관계를 유지한다. 시간 상수 0.25초, 경계/경로 변화 상한은
각각 40px/s의 시험값이다. 프레임 간 실제 시간으로 계산하며 긴 정지 후
허용 이동량이 커지지 않게 한다. 최종 곡선 전체를 연결된 영역과 비교하고,
유효하지 않으면 이전 선을 억지로 유지하지 않고 무효화한다. 따라서 무효화·
재초기화 구간의 표시 중단까지 없애는 보장은 아니다.

## 표시와 기존 출력

흰색 실선은 실제 기준, 주황색 점선은 가상 경계, 하늘색 실선은 주행경로다.
결과 영상과 BEV에 적용한다. BEV 투영은 기존 미보정 개발 투영을 사용한다.
기존 boundary 텔레메트리는 원시 추적 진단으로 남기고 선택된 결과는
`guidance_*` 필드로 구분한다. 기존 `centerline_valid=False`,
`coefficients=None`은 유지한다. 기존 CSV 열은 변경하지 않아 새 필드는
검증기의 원본 `frames.jsonl`에 저장한다.

`virtual_guidance.json`의 enabled 또는 `OAK_VIRTUAL_GUIDANCE=0`으로
새 계산/표시를 비활성화할 수 있다. 설정은 서비스 시작 시 읽는다.

## 배포와 롤백

저장소 변경 전 기준 커밋은 `4a9995e`. 기존 미추적 PDF 2개는 건드리지 않았다.
로컬 변경 전 파일·해시·상태·패치는 다음에 보존했다.

`artifacts/virtual_guidance_20261028/rollback/`

장치 최종 배포의 원본 파일과 manifest는 `rollback/device_final/`에 있다.
이 폴더의 manifest/deployment JSON과 백업 파일을 함께 보존해야 한다.
신규 파일이 원래 없었다는 사실도 manifest에 기록한다.

실제 첫 배포본을 `rollback/device_v2/`로 복원하는 시험을 수행했다.
원래 yolopv2_node.py SHA256
`60fbec78168584a8d27f7d23f0be16ae0fa6b2ad38f3b5de3e69f9a91da983d9`
일치와 신규 두 파일 제거, main/postprocess/추적기/설정 해시 유지를 확인했다.
그 뒤 동일 원본을 다시 snapshot하고 최종 보완본을 배포했다.

장치의 postprocess는 여전히 오래된 320 고정 API이므로 배포 도구가
node의 해당 함수 호출 인자만 설치본에 맞춘다. postprocess와 main 자체는
교체하지 않는다. 실제 배포된 node는 backup 폴더의
`deployed_yolopv2_node.py`에 보존하며 저장소 node와 바이트가 다르다.

저장소 루트 PowerShell에서 원상 복원:

```powershell
python src/hl_camera_bringup/scripts/manage_virtual_guidance.py rollback --device-ip 192.168.201.2 --backup artifacts/virtual_guidance_20261028/rollback/device_final
```

도구는 배포 후 파일이 다른 작업으로 변경됐으면 덮어쓰지 않고 중단한다.
원본 해시 확인, 새 파일 제거, 서비스 재시작, context 파일 해시 확인을 수행한다.
이는 소스 롤백이며 PC 소스/처리 모드까지 자동 복원하지는 않는다.
영구 앱 이미지 재빌드나 원격 Git push는 하지 않았다.
