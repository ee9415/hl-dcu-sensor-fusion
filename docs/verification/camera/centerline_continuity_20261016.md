# 실영상 중심선 연속성 보완

작성일: 2026-10-16

## 변경

- 일부 경계 이상으로 전체 프레임을 무효화하던 조건 대신 지원되는 전방 구간을 피팅한다.
- 유효 관측의 큰 차이는 재획득 대기로 보내지 않고 기존 이동 속도 제한으로 처리한다.
  관측 소실 후 복구 및 초기화에는 확인 기간을 유지한다.
- 통로 보정 피팅 실패 시 현재 측정의 잔차가 0.5 이하이고 95% 이상이 현재 영역
  안에 있으면 측정값으로 복귀한다. 복귀값에도 시간 필터를 적용한다.
- 경계 비교 기준과 시간 필터의 거리 범위가 계속 교집합으로 축소되는 문제를 수정했다.
- 현재 마스크 안에 이전 중심이 포함되는 경우 contained_prior로 구분해 이어간다.
  이것은 차로 인식 확정 상태가 아니며 조향 입력으로 검증되지 않았다.
- 현재 단일 경계가 관측되는 상태를 시간 초과로 만료시키지 않는다. 마스크 미관측은
  기존 시간 필터의 제한된 hold 이후 무효 처리한다.
- 가중 반복 최소제곱 3차식 피팅으로 이상치 영향을 줄이고, 마스크 내부 연속 구간만 표시한다.
- 도로 표식으로 생긴 좁은 행 방향 틈을 연결한다. 최대 폭은 마스크 너비 4%이며
  320픽셀 입력에서 12픽셀이다. 더 넓은 빈 영역은 연결하지 않는다.

## 검증 방법과 제한

- Ubuntu unittest 28개 통과. 부분 경계 손상, 표시 범위 회복, 지속 단일 경계,
  현재 영역 포함, 미관측, 좁은 표식 틈, 넓은 빈 영역 분리 회귀 테스트 포함.
- 실제 OAK가 모니터의 도로 영상을 촬영하는 상태에서 여러 차례 30초 RTSP 녹화와
  5초 간격 HEALTH 로그를 대조했다. 실제 차량 주행 검증은 아니다.
- 녹화 결과는 artifacts/centerline_*_recheck 아래 로컬 보관한다. 대용량 MP4는 커밋하지 않는다.
- check_centerline_video.py의 단순 색상 행 검출은 박스/배경색 혼입이 있으므로
  급변 수치를 그대로 중심선 이동으로 해석하지 않는다. 별도의 연결 성분 기반
  analyze_centerline_recording.py도 짧은 선을 미검출할 수 있으며 안전성 지표가 아니다.
- 최초 보완 녹화에서는 실제 소실을 확인했고, 2차 보완에서는 293프레임 중
  연결 성분 검출 실패 35프레임, 최장 18프레임이었다. 이 중 실제 소실 프레임을
  이미지로 확인했다. 이후 틈 연결까지 추가해 재검증했다.
- 배포 직후 시작한 GUI 검사는 포트 준비 이전이라 실패했다. 이를 영상 수신 정상의
  근거로 사용하지 않는다. 최종 녹화 성공 여부는 별도 기록한다.

## 적용 제한

고정 호모그래피의 개발용 BEV 스케일이다. 차속/요레이트 입력이 없으므로 실제
자차 운동 보상은 없다. 과거 중심이 현재 주행 영역 안에 있다는 사실만으로
올바른 차로나 안전한 조향을 보장하지 않는다. 작은 틈 연결도 얇은 장애물과
차선 표식을 완전히 구분하지 못한다. 객체/Depth 기반 장애물 배제는 별도 필요하다.
