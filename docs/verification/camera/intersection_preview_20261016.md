# 교차로 좌우 선회 경로 미리보기

작성일: 2026-10-16. oakapp 0.11.0.

## 범위와 사용법

일반 도로의 기존 보수적 1/2차 중심선 처리는 변경하지 않았다.
멀티뷰 하단의 `좌회전 미리보기`, `우회전 미리보기`, `일반 도로 복귀`로 조작한다.
교차로 자동 검출이나 차량 제어가 아니라 수동 방향 지정에 따른 경로 형상 검증 기능이다.
현재 유효 중심선과 충분한 가시 길이가 있어야 선회 요청을 수락한다.
활성 선회 중 반대 방향 요청은 거부하며 일반 도로 복귀를 먼저 해야 한다.
명령 수락과 전환 완료는 다르다. UI는 수락 여부, BEV는 모드/전환 상태를 표시한다.

## 경로 모델 및 연속성

일반 경로는 y(x), 선회 미리보기는 x(s), y(s) 표본이다. 일반 중심선의 계수에
선회 경로를 억지로 재피팅하지 않는다. 기존 HEALTH의 centerline 계수는 일반 경로
값이며 turn_preview_mode/status/control_eligible로 선회 표시 상태를 별도 구분한다.

- 일반 중심선을 호 길이로 재표본화(최대 24 개발 단위, 241점).
- 앞쪽 1/6 구간은 그대로 보존한다.
- 연결점의 위치/접선/곡률에서 시작하는 heading Hermite 함수를 호 길이로 적분한다.
- 끝 방향은 연결점 기준 좌/우 90도, 끝 곡률은 0이다. 실제 출구 차로 추정은 아니다.
- 출력 위치를 프레임마다 최대 0.5×min(dt,0.1) 개발 단위만 이동시킨다.
- 표본 접선 변화 0.05 rad/s, 이산 곡률 변화 0.005 개발 역거리/s 제한도 적용한다.
- 일반 도로 복귀 역시 현재 일반 중심선으로 제한 속도로 보간한다.
- 관측이 무효이면 선회 표시를 숨기고 전환을 멈춘다. 재관측 후 제한 속도로 진행한다.
- 선회는 보라색, `TURN PREVIEW ONLY`로 표시. BEV는 일반 화면과 다른 고정 광역
  스케일이며 프레임마다 자동 확대/축소하지 않는다. 영상 투영 밖 부분은 그리지 않는다.

엄격한 개발용 변화 제한 때문에 최종 90도 형상까지 수십 초 이상 걸릴 수 있다.
이는 경로 표시 전환 시간이지 실제 차량의 선회 소요 시간이나 권장 주행 속도가 아니다.
출력 선회 경로는 선택 당시 카메라 좌표에 고정된 미리보기로, 차량 이동에 맞춰 갱신되는
주행 궤적이 아니다. 속도/요레이트/위치 기반 보상과 출구 차로 연결은 미구현이다.

## 명령 전달

새로운 비인증 네트워크 포트를 열지 않는다. 기존 oakctl 인증을 이용하여 개발 앱
내 `/app/turn_command.py left|right|road`를 실행한다. UUID별 원자적 파일 메일박스와
실제 프레임 처리 루프의 수락 응답을 사용한다. 10초 초과 명령은 거부하고 프로세스
재시작 시 기존 명령을 재실행하지 않는다. 응답 대기는 5초, UI 실행 제한은 15초다.
현재 UI 대상은 기존 개발 앱 ID(모두 0)다. 설치형 앱 ID 지원은 별도 작업이다.
Ubuntu에 별도 oakctl이 없으면 WSL의 Windows oakctl.exe를 사용해 기존 인증을
재사용한다. Windows 실행파일로 앱을 배포할 때 소스 경로도 wslpath로 변환한다.

## 검증

- Ubuntu 테스트 48개 통과: 좌우 대칭, 90도 끝 방향, 곡선 진입 연결 곡률,
  프레임별 위치/접선/곡률 제한, 일반 도로 복귀, 무효/중복/역순 입력,
  명령 만료/재시작/응답, 투영 특이점과 호모그래피 부호 불변성.
- 합성 이미지: artifacts/turn_preview_20261016/synthetic_contact.jpg.
  진입각 약 1.146도에서 끝 방향 좌 -88.852도 / 우 91.144도 확인.
  합성 결과는 실제 교차로 주행 영상이 아니다.
- 카메라 배포 후 좌회전/우회전/도로 복귀 명령 수락 확인.
- 실제 RTSP BEV 선회 표시 확인. 초기 실기 검사에서 발견한 미지원 글꼴과
  호모그래피 분모 부호 처리 문제를 수정하고 회귀 테스트를 추가했다.
- Ubuntu 멀티뷰 창, RGB 1920x1080 / YOLO 960x540 / BEV 640x480 수신 및
  ImageTk 미리보기, 새 선회 조작 구성 확인. 창은 열어두었다.
- Ubuntu UI 요청 검사에서 누락된 oakctl 경로를 발견하여 Windows CLI 폴백 추가.
  수정 후 UI의 일반 도로 복귀 요청 수락을 확인했다. RTSP 검사 중 중복 창과
  재배포 이후 일부 스트림 연결 실패/영상 압축 깨짐도 관측하여 무중단 수신은 보장하지 않는다.
- ROS topic/TF/namespace 변경 없음. 독립 카메라 앱/UI 변경으로 colcon 검증 미실시.

## 안전 및 남은 작업

사용자는 차량 제원을 아직 모른다고 답했다. 현재 거리와 곡률은 미보정 개발 좌표다.
선회 경로의 장애물 충돌, 주행 가능 영역 포함, 출구 차로 도달, 실제 조향각/조향 속도,
동역학적 실행 가능성은 검증하지 않았다. `control_eligible=False`이며 차량 제어로 보내지 않는다.
실제 교차로 주행 적용 전 카메라 보정, 차량 제원, 출구 목표, 차량 운동 정보,
충돌 검사 및 현장 검증이 필요하다. 현재 모니터 재생 도로 영상은 교차로 주행 검증이 아니다.
