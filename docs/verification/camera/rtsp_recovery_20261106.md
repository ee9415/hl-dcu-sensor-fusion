# RTSP 입력 단절 후 연결 복구 (2026-11-06)

## 문제와 확인

멀티뷰에서 영상 연결을 요청하면60초 후 RGB/YOLO/BEV/Depth 포트 준비 실패가 발생했다.
CAM01의0.33.4 앱은 running이었으나8553~8556 TCP 연결은 모두 시간 초과였다.
8557 텔레메트리와8558 입력 제어 포트는 열려 있었다. 디스크는60GB 여유가 있어
공간 부족은 아니었다. 당시 로그는 artifacts/source_apply_20261106/connection_camera*.log.

RTSP의 need-data 콜백이 입력 큐가 빌 때 무기한 대기했다. 프레임이 없는 PC 입력에서
클라이언트가 종료되면 미디어 종료가 콜백 반환을 기다릴 수 있으므로, 콜백을 깨우는
unprepared 신호에 의존하는 구조는 종료 순환 대기를 만들 수 있었다.
빈 입력에서 콜백이 반환하는지를 검사하는 회귀를 추가했다.

## 수정

- need-data/enough-data 콜백은 수요 상태만 바꾸고 즉시 반환한다.
- 팩토리별 단일 작업 스레드가 프레임을 기다리고 순서대로 appsrc에 전달한다.
- 큐·수요·소스 세대는 같은 조건 잠금으로 보호하고 push-buffer는 잠금 밖에서 실행한다.
- 이전 미디어 콜백 격리, 큐 초과 후 IDR/SPS/PPS 복구는 유지한다.
- unprepared에서는 소스와 수요를 해제하고 이전 작업의 반환값이 새 미디어를 정지시키지 않는다.
- 버전0.33.5. 차선 추적 알고리즘 변경은 없다.

## 검증

RTSP 회귀6개 통과: 빈 입력의 콜백 즉시 반환, 순서/역압 제어,
키프레임 초기화·큐 초과 복구·새 연결 초기화·이전 콜백 격리.

실장치 검사는 verify_rtsp_recovery.py로 수행한다. 카메라 영상을 받은 후 프레임 없는
PC 입력을 선택하고8초 대기해 수신기를 종료한다. 입력이 없는 상태에서4개 포트에
3차례 연결하고 카메라로 복귀하여4개 스트림의 재수신을 확인한다.
검사 후 입력은 카메라로 복원한다. 소실 중의 디코더 읽기 시간 초과는 의도한 조건이다.

단계 적용 백업 `/app/deploy_backup_9bc497f4c5`.
최종 패키지와 반복 검사 결과는 artifacts/rtsp_recovery_20261106에 기록한다.
