# 차선 재관측 시 경계 복귀 검증

작성일: 2026-10-21 | 수정/배포 버전: 0.18.1

## 발견 사항

사용자 요청으로 열린 Ubuntu 멀티뷰와 연속 CSV를 확인했다. 0.18.0 세션
`732fc3b3-5bcc-42a5-81be-ada8719802d3` 초기 1909프레임의 inferred/held → observed
전환 68건 중 9건에서 공통 전방 좌표의 이동량이 설정 속도 제한을 넘었다.
긴 소실 뒤 사례에는 왼쪽 약 29.8초 후 1.595 개발 단위, 오른쪽 약 37.3초 후
4.161 개발 단위 이동이 포함됐다. 0.1초 프레임의 의도한 제한은 약 0.1 개발 단위다.
도로 마스크 밖에 있는 이전 경계를 평활 기준에서 제외하는 분기가 원인이었다.
모니터 영상 촬영의 한정된 표본으로, 수치는 실제 미터 단위가 아니다.

## 수정

도로 마스크 변경에도 이전 표시 경계를 보정 시작 위치로 사용한다. 기존
`max_lateral_rate_m_s` 설정으로 공통 관측 구간 이동을 제한한다. 도로 지지 검증은
평활 중간 위치 대신 원시 흰색선 관측에 적용한다. 이로써 천천히 접근하는 표시가
새 도로 마스크에 도달하기 전에 숨겨져 버리는 문제를 방지한다.
관측 연관 기준은 계속 원시 측정값으로 갱신하므로 평활 지연 때문에 표식을 놓치지 않는다.
장기 소실 유지, 좌우 독립 처리, 중심선 제외는 유지한다.

## 검증 결과

- 전체 unittest 80개 통과. 새 사례는 6초 소실 후 양쪽 표식이 1.5 개발 단위
  이동하여 이전 왼쪽 경계가 새 도로 밖에 놓이는 조건이다. 모든 보정 프레임에서
  좌우 경계를 유지하며 이동량 ≤0.100001, 최종 좌표는 새 표식에 수렴했다.
- 개발 앱 중지/run 배포 후 `OAKAGENT_APP_VERSION=0.18.1` 확인.
- 장비 `/app/lane_boundaries.py` SHA256:
  `61c3ae4d651cf7167cd6adc574dc7464e36706b359095fc5e1be3ee4365acb28`.
- 멀티뷰 재연결 후 네 영상 수신 확인. 별도 RTSP 수신도 RGB 1920×1080,
  결과 960×540, Depth 640×360, BEV 640×480 성공. 일시적인 영상 압축 블록이
  관찰되어 화면 스냅샷만으로 움직임을 판단하지 않고 프레임 좌표도 대조했다.
- 세션 `1f58eadb-305f-4ed9-ae0f-a6fa3686ba46` 초기 391프레임에서 복귀 전환
  15건, 공통 구간 속도 제한 초과 0. 좌측 6.00초/5.40초, 우측 3.80초/2.10초
  소실 후 복귀 포함. 약 0.1초 간격에서 최대 이동은 각각 약 0.1 개발 단위로 제한됨.

## 재현 및 한계

`src/hl_camera_bringup/scripts/audit_boundary_return.py`에 CSV 경로와 `--output`
JSON 경로를 전달한다. 최신 세션의 연속 frame_seq/정상 시간 간격만 대상으로
양 프레임에 모두 존재하는 전방 좌표의 최대 횡이동을 계산한다. `--rate`는 배포
설정과 일치시킨다(기본 1.0). 신규 표시 범위의 끝점은 이전 좌표가 없어 이 비교에서
제외된다. 표식이 짧게 나타나거나 잘못 인식되는 경우의 끝점 변화까지 없다는 뜻은 아니다.

실영상 흰색선의 정답 픽셀 오차, 실차 이동 보상 및 한라대 실차 검증은 미수행.
모니터 촬영/미보정 IPM 조건이므로 물리 거리 정확도 보장으로 해석하지 않는다.
ROS2 경로 변경이 없어 colcon/TF/topic 검사는 해당하지 않는다.
