## 확인된 프로그램 문제

기존 SharedRgbRecorder는 MP4 저장 스레드 안에서1초마다 CAM01의 TCP8558 상태를
동기적으로 확인했다. 연결·읽기는 각각 최대2초를 기다릴 수 있는데, 같은 스레드가 녹화 일정을
1초 넘게 놓치면 이를 무조건 "저장 지연"으로 처리했다. 따라서 디스크 쓰기가 정상이어도
정상 상태 응답이1.2초 걸리면 저장 오류로 종료될 수 있었다. 한 카메라 오류 시 그룹 전체를
정지하는 정책 때문에 나머지 영상도 같이 끝난다.6분/10분 고정 녹화 시간 제한은 없다.

변경 전 코드에 상태 응답1.2초 지연만 넣어 동일 오류 종료를 재현했다. 실제 카메라나
네트워크를 쓰지 않았고 저장 지연은 주입하지 않았다. 근거:
artifacts/recording_review_20261103/before_guard_latency_report.json.

과거 CAM01의3건 모두가 이 지연 때문이었다고 단정할 수는 없다. 당시 로그에 상태 응답,
프레임 복사/크기변환/실제 write 시간을 따로 남기지 않았으므로 CPU/스케줄링/실제 저장
지연도 구분되지 않는다. CAM02의 수신 끊김은 별도 유형이며 장치/PoE/네트워크/호스트 수신
문제 중 어느 쪽인지는 장비 없는 현재 상태에서 확정할 수 없다.

## 수정

- 반복 상태 확인을 별도 모니터 스레드로 분리해 정상적인 느린 응답이 MP4 일정에
  영향을 주지 않도록 했다. 실제 상태 확인 실패·소스 전환·수신 끊김은 계속 종료한다.
- 실제 녹화 처리 일정 초과는 recording_schedule_overrun으로 분류한다. 이 값은
  디스크 고장이라는 뜻이 아니며 CPU/프레임 처리/스케줄링 지연도 포함한다.
- session.json에 오류 종류, 최대 상태 응답/프레임 스냅샷/resize/write 시간,
  최대 일정 지연, 마지막 프레임 나이, 오류 종료에서도 경과 시간을 기록한다.
- 각 카메라 폴더에 recording_events.jsonl을 만들고 시작/5초 간격 상태/종료를 기록한다.
  session.json은 임시 파일 후 교체하여 부분 JSON 위험을 줄였다.
- OAK-D 연결 시 artifacts/connection_logs/CAMxx_<시각>_<ID>.jsonl에 worker 시작,
  최초 RGB 연결, worker 종료코드/오류/stderr/마지막 패킷 나이를 기록한다. 재접속 후에도
  last_failure를 유지한다. 정리용 terminate가 원래 종료코드를 덮어쓰지 않도록 보완했다.
- 실제 수신 끊김이나 저장 일정 초과를 무시하고 계속 정상 녹화로 표시하지는 않는다.
  기존 그룹 오류 정지 정책과 실제·가상 입력 구분은 유지한다.

## 검증

- 느리지만 정상적인 상태 응답1.2초를 넣은 수정 후 검사는 녹화가 유지된다.
- 실제 writer.write1.2초 지연은 별도로 주입해 일정 초과 분류/max_write_ms/부분 파일
  종료 로그와 경과 시간이 기록되는 것을 확인했다.
- OAK-D worker 실패의 원래 종료코드와 stderr 연결 이력 기록 검사 통과.
- 전체214개 검사 및 기존 Tk 탭/전송·표시 제어 검사가 통과했다.
- 12분6가상 영상 연속 검증 통과: 실제 경과720.15초,6개 MP4 정상 종료 및 디코딩 확인.
  한 개1920×1080, 다섯 개1280×720, 저장10FPS. 느린 상태 응답1.2초를 반복 주입해도
  중단되지 않았다. 확인한 최대 실제 write 시간은 약129.5ms였다.
- 장시간 검증은 수신·녹화 백엔드 경로를 실행하며, 장시간 Tk 렌더링이나 실장치/네트워크
  검증은 아니다. 단순 가상 패턴은 실제 도로 영상과 압축률·인코딩·저장 부하도 다르다.
- 근거: artifacts/recording_review_20261103/long_run.py, long_run_report.json,
  long_run_progress.json 및 long_run_12min 하위6개 영상/각 recording_events.jsonl.

기존 로그 분석 및 MP4 확인: artifacts/recording_review_20261103/sessions_analysis.json.
호스트 수정 전 원본: artifacts/recording_review_20261103/host_before.
카메라 앱/모델 변경 없음. 멀티뷰 재시작 후 호스트 수정이 적용된다.
