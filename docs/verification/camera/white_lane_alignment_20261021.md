# 실제 흰색 차선 정렬 경계선

작성일: 2026-10-21 | 최종 소스/카메라 개발 앱: 0.16.2

## 요구사항과 변경 근거

사용자가 제시한 영상의 좌우 흰색 차선 위치에 가상 경계선을 정렬한다.
0.15.x의 차량 폭+여유 폭 고정 통로는 요구와 달랐으므로 해당 제약을 제거했다.
중심선 계산·표시·목표점·선회 경로는 계속 제외한다.

- NN 차선 마스크 주변에서 RGB의 흰색/회색 국소 밝기 피크를 선택한다.
  녹색 영역, 폭이 넓은 수평 표식을 배제한다. 수평 주차칸·노면 표식 오인식은
  모든 조건에서 해소된 것이 아니며 추가 현장 검증이 필요하다.
- 처음에는 카메라 축의 좌/우에서 가까운 세로 방향 표식을 각각 취득한다.
  이후 좌우 각각의 이전 경계와 연관시켜 강건 2차식으로 독립 피팅한다.
  두 선의 중간점을 만들거나 중심선에 폭을 더하지 않는다.
- 차량 폭+좌우 여유는 최소 통과 폭 점검에만 사용한다. 실제 경계가 그보다
  좁게 추정돼도 위치는 유지하고 `insufficient_width` 상태를 표시한다.
- 한쪽 표식 소실 시 이전에 관측한 폭 분포와 반대 경계의 변화를 이용한다.
  양쪽 소실 시 이전 형상을 최대 `max_lane_gap_s`(초기 2초) 이어간다.
  먼 외곽으로 급변하는 후보는 배제하며 만료 후 표시를 중단한다. 만료만을 이유로
  넓어진 도로 외곽을 즉시 새 차선으로 취득하지 않도록 기존 연관 기준을 보존한다.
- 초기 양쪽 표식이 없는 도로에서 차폭만으로 통로를 생성하지 않는다.
- 차선/도로가 관측된 범위만 표시한다. 가까운 화면 아래에 마스크가 없다는 이유로
  더 앞의 정상 관측까지 폐기하던 조건을 수정했다. 먼 곡선 교차나 도로 충돌은
  표시 범위를 줄이거나 무효 처리한다.
- 결과 영상의 굵은 빨간 NN 차선 마스크를 숨기고 주행 영역을 약하게 합성하여
  실제 흰색선과 노랑/하늘색 가상 경계의 정렬을 확인할 수 있게 했다.

## 설정·데이터 호환성

`apps/yolopv2_standalone/lane_boundaries.json`의 차폭 1.8, 좌/우 여유 0.3/0.3은
계속 조정 가능하며 실차 측정값은 아니다. `max_lane_gap_s=2.0`을 추가했다.
앱 시작 시 읽으며 설치 앱은 재빌드/배포가 필요하다.

CSV에 `minimum_clearance_width_m`, `boundary_width_min_dev`,
`boundary_width_max_dev`, `clearance_sufficient` 추가. 기존 `corridor_width_m`는
호환성을 위해 설정된 최소 폭의 별칭으로 유지하며 실제 관측 차선 폭을 뜻하지 않는다.
실제 폭 분포는 같은 인덱스의 `right_boundary_dev-left_boundary_dev`다.
중심선 계수는 계속 빈 값, 중심선 유효성 false, 선회 disabled다.

미보정 IPM 때문에 실제 차선도 전방 구간별 개발 폭이 다르게 계산될 수 있다.
`insufficient_width`나 `clearance_sufficient`는 물리적 차량 통과 가능 판단으로
사용할 수 없다. 차량 장착 보정·실측·가림/교차로/차선 변경 평가는 별도 필요하다.
RGB/객체/Depth/녹화/CSV 및 RTSP 주소와 기존 전송 식별자는 보존했다.

## 0.16.1 정렬 검증 방법과 결과

- Windows 번들 Python/NumPy에서 전체 72개 테스트 통과.

  경계 위치의 독립성 검증으로 변경했다. 한쪽 소실 시 관측 폭 유지, 급확장 배제,
  시간 만료, RGB 흰색 피크, 가로선 폭 제한, 근거리 미관측 처리 포함.

  아닌 관측된 폭을 송신하는지, 결과/BEV 크기·시각·번호가 유지되는지 확인했다.
- 갱신한 TCP CSV 테스트에서 관측 폭/최소 여유 열과 무효 폭의 빈 값 저장 확인.

  임시 마스크 저장 진단 코드는 최종 배포에서 제거했다.
- 카메라 내부 SHA256(줄바꿈 LF 기준):
  `lane_boundaries.py`: `fd36b6a406c02d86f2594b3bf440815ff1473ee755bd15c12eb49eeb76b83e5c`.
  `yolopv2_node.py`: `522fd67b47adae523c98ddba8b49f91d6eb495ade0d8e008ae34b59366ba5cdf`.
- Ubuntu 멀티뷰에서 네 영상 수신과 중심선·목표점·선회 버튼 제외를 확인했다.
  별도 RTSP 직접 수신에서도 RGB 1920×1080, 결과 960×540, Depth 640×360,
  BEV 640×480을 확인했다.
- 화면 비교는 기존 한라대 도로 재생 영상의 흰색선 구간을 정지/재생하여 수행했다.
  정지 구간에서 실제 흰색선에 노랑/하늘색 경계가 정렬됨을 육안 확인하고,
  재생 후 이동 중 표본을 추가 확인했다. 멀티뷰와 도로 영상은 재생 상태로 유지했다.

전체 상태: tracking 659, insufficient_width 316, road_unavailable 4,

`insufficient_width`도 관측 경계는 표시하므로 유효 프레임에 포함한다.
선택한 정지 표본의 개발 폭은 약 2.39~5.73으로 구간별 변화하여 기존 고정 2.4
제약이 사라졌음을 확인했다. 이 수치는 실제 차로 폭 측정 결과가 아니다.
최종 로그 표본의 평균 9.9 FPS, 후처리 약 69.96 ms를 확인했다.

이 비율은 검출 유효 상태 통계이며 경계 위치 정확도나 모든 장면의 무소실 보장이
아니다. 현재는 모니터를 카메라로 촬영한 시험이다. 실제 차량의 한라대 주행 시험,
거리 정확도, 경계 정답 대비 픽셀 오차의 정량 검증은 미수행이다.
NN의 차선 오검출, 그림자, 주차 차량 가림, 주차칸 가로선, 장기 표식 소실과
교차로 경로 선택은 남은 검증/개선 항목이다. ROS2 실행 경로가 아니므로
colcon/topic/TF 검증은 해당하지 않는다.

문제를 보완했다. 별도로 새 좌우 후보를 피팅하고, 이전 폭의 중앙값 대비 1.25배를
