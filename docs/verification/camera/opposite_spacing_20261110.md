# 반대편 형상·기존 간격 유지 적용 (2026-11-10)

## 요구사항과 변경

사용자 요구에 따라 한쪽이 잘 보이고 반대쪽이 미검출이면, 미검출 쪽을 보이는 쪽의 현재 형상에 맞추면서 마지막 신뢰 간격을 유지하도록 변경했다. 종전의 미검출 고유 휨 보존+반대편 변화량 전달 방식은 이 요구를 충족하지 않아 교체했다.

- 양쪽을 실제 관측하고 표시가 정렬된 프레임에서만 기존 간격을 학습한다. 가상 선이나 미검출 보정으로 간격·관측 시각·신뢰도를 학습/갱신하지 않는다.
- 3회 이상 측정된8행 이상·세로20px 이상의 신뢰 간격으로 1차 원근 간격 프로파일을 적합한다. RGB에서는 원근에 따라 폭이 달라져야 하므로 고정 픽셀 폭을 사용하지 않는다. 옛 좌우 곡률 차이를 그대로 폭으로 복사하지 않는다.
- 목표는 현재 오른쪽 형상−원근 간격(왼쪽 미검출), 또는 현재 왼쪽 형상+원근 간격(오른쪽 미검출)이다. 기존 표시 영역에서만 적용하며 처음부터 한 번도 보지 못한 반대쪽은 만들지 않는다.
- 반대편 관측 지지가8행·20px 이상일 때만 유도한다. 신뢰 간격이 없거나 양쪽이 모두 미검출이면 기존 형상을 유지한다.
- 기존 점진 수렴·최대 이동 속도·쌍 유효성 검사는 유지한다. 사용자 반응 속도를 초기화하지 않는다. telemetry에 opposite_shape_spacing, spacing_reference, spacing_target_error_px, spacing_rows를 기록한다.

## 코드 검증

- 최종 WSL 전체 회귀394개 통과(62.347초). 좌우 대칭 직선 복원, 반대쪽 곡률 추종, 이동 상한, 미검출 간격 학습 금지, 간격 미학습 시 유지, 최초 미관측 선 생성 금지를 포함한다.
- 이전 요구인 미검출 원래 곡률 보존 테스트를 현재 요구인 반대편 형상·원근 간격 수렴 검사로 변경했다. 표시 설정 독립성 검사는 서로 다른 표시 설정을 사용하는 두 처리기의 추적 결과 비교로 보강했다.
- 기존 저장 마스크631프레임을 3배 속도로 재생 검증했다. PC ONNX FP32 결과는 실장치 FP16/전송 결과의 정확한 대체나 정답 정확도 지표로 사용하지 않는다.
