# OAK4 + OAK-D 혼합 6대 연결·녹화 (2026-11-02)

## 후속 실장치 확인: CAM02

사용자가1·2번을 실제 연결한 뒤 확인 요청. CAM01은192.168.201.2에서1920×1080
RGB 수신 확인. CAM02는 Windows 네이티브 DepthAI2 검색에서 IP192.168.201.5,
MX19443010E131771300으로 발견됐다. WSL 자동 검색은 빈 목록이었지만 WSL 수신기에
IP를 직접 지정하자 실제1280×720 RGB10프레임을 받았다. MX 일치, virtual=false,
재접속0을 확인했고 수신기를 종료했다. CAM01의 저장 앱은 ready 상태여서 기존 앱만
시작했으며 코드 재배포는 하지 않았다.

근거: artifacts/oakd_cam02_06_20261102/cam02_hardware_report.json,
cam02_hardware_rgb.jpg, verify_cam02_hardware.py.
아래 작업 당시의 CAM02 미검증 설명은 이 수신 확인으로 갱신된다.
CAM02 실제 녹화/장시간 성능과 CAM03~06 실장치 확인은 아직 남아 있다.

## 적용 범위

- CAM01: 기존 OAK 4D Pro PoE 앱의 RGB 수신기 공유를 유지한다. 인식·검증 탭의
  RGB/결과/Depth/TOP 및 기존 독립 녹화와 CSV 동작을 유지한다.
- CAM02~06: 카메라별 별도 프로세스에서 DepthAI 2로 IP 또는 MX ID에 접속하고
  RGB MJPEG를 받아 멀티뷰에 표시한다. 카메라 내부 RGB 인코더를 쓰며 NN/Depth는
  새로 실행하지 않는다. 수신 설정은1280×720/10FPS, 저장 설정과는 별개다.
- 각 카메라에 실제 OAK-D / 가상 영상 중 하나를 명시적으로 선택한다.
  실제 장치 연결 실패 시 가상으로 자동 대체하지 않는다.

## 사용 순서

1. 멀티뷰를 재시작하고 `6대 카메라 녹화` 탭으로 이동한다.
2. `카메라 설정`에서 CAM02~06의 IP/MX ID와 입력 종류를 정한다.
   장비가 없으면 `가상 영상`을 선택한다. 실제 입력에는 IP 또는 MX ID가 필요하며
   둘 다 지정하면 연결된 장치의 MX ID도 확인한다. 같은 장치를 중복 배정하면 거부한다.
3. 실제 OAK-D의 `OAK-D Python`은 DepthAI 2 환경의 Python 실행 파일을 지정한다.
   가상 영상은 멀티뷰의 Python으로 실행하며 DepthAI 설치가 필요하지 않다.
4. 각 카드의 `연결` 또는 체크박스로 대상을 고른 뒤 `선택 카메라 연결`을 누른다.
   `[가상]` / `[실제]`와 연결 상태, 오류, 재접속 횟수를 확인한다.
5. 저장 폴더/세션 이름/저장 해상도/FPS를 확인하고 `선택 카메라 녹화 시작`을 누른다.
   선택한 모든 카메라가 연결돼 있어야 시작한다. `녹화 정지`로 전체 파일을 마무리한다.
6. 연결 해제는 카드별 `해제`. 녹화 중 연결 변경은 막는다. CAM01은 기존 탭과
   공유하므로 새 탭에서 공유 수신기를 강제로 해제하지 않는다.

설정은 이번 실행 중에만 유지된다. 재접속은 미리보기 수신을 복구하지만, 오류로
중단된 녹화를 자동 재시작하지 않는다. 연결을 확인하고 새 세션을 명시적으로 시작한다.

## 저장 구조

```text
<저장폴더>/<세션>_<시각>_<ID>/
  recording_group.json
  cam01/cam_01_rgb.mp4
  cam01/session.json
  cam02/cam_02_rgb.mp4
  cam02/session.json
  ...
  cam06/cam_06_rgb.mp4
  cam06/session.json
```

선택한 카메라만 생성한다. JSON에 카메라 이름/모델/실제·가상 입력 종류/원본URL/
IP·장치ID/저장FPS·크기/프레임 수/반복 수/오류를 기록한다. MP4는 PC에서 mp4v로
재인코딩한다. 가상 영상 자체에도 CAMxx VIRTUAL 표시를 넣어 실제 녹화와 구분한다.
새 그룹 녹화는 별도 프레임/객체 CSV를 추가하지 않는다.

녹화 중 한 대가 끊기거나 입력 재연결·소스 전환·저장 오류가 발생하면 그룹을
정지하고 파일을 마무리한다. 짧은 재접속도 주기적 입력 상태 확인으로 감지한다.
부분 파일과 오류는 유지하며 정상 전체 녹화로 취급하지 않는다. 창을 닫을 때도
녹화와 모든 OAK-D 수신 프로세스를 종료한다.

## 별도 DepthAI 2 환경

현재 WSL에는 다음 검증용 환경을 준비했고 설정 창에서 자동 선택한다.

```text
/mnt/d/git_hub/hl-dcu-sensor-fusion/artifacts/oakd_runtime/.venv/bin/python
DepthAI 2.32.0.0
```

기존 시스템에 ensurepip/pip가 없어 별도 venv를 생성한 뒤, PyPI의 해당 Linux 휠을
그 venv의 site-packages에만 배치했다. 시스템 Python/기존 OAK4 앱은 변경하지 않았다.
복제한 다른 환경에서는 정상적인 venv와 pip가 준비된 상태에서:

```bash
python3 -m venv .venv-oakd
.venv-oakd/bin/python -m pip install -r tools/oakd_rgb_requirements.txt
```

그 Python 경로를 `OAK-D Python`에 지정한다. Windows에서 실행한다면 Windows용
venv/Python 경로를 사용한다. DepthAI 3/누락된 SDK/잘못된 실행 파일은 명확한 오류로
표시하고 가상 입력으로 바꾸지 않는다.

공식 자료: [DepthAI 2.32 배포](https://pypi.org/project/depthai/2.32.0.0/),
[Luxonis v2 MJPEG 예제](https://docs.luxonis.com/software/depthai/examples/script_mjpeg_server).
