# person 모델 FPS 및 병목 계측 (2026-10-27)

## 결론

대표 PC 영상의 실제 결과 발행 처리량은 **8.64 FPS**다. 경계선 후처리와 영상 렌더링에 우선 개선 여지가 있다. 순수 NPU 추론이 병목이라고 판정할 근거는 아직 없다. 알고리즘/검출 기준은 변경하지 않았으며 임시 계측 소스는 원본과 바이트 단위 일치하도록 복구했다.

## 조건 및 FPS 정의

- OAK4-D Pro 1142227768/192.168.201.2, 새 person RVC4 모델, 기존 모델 전처리/경계 추적 설정 유지.
- 20261026_174939_70502991의 RGB 녹화2~18초 구간을20초 반복. 목표 송신10Hz, 정지/재개 검증 구간은 연속 FPS 계산에서 제외.
- 정상 실행198프레임 반환. 연속 창176프레임의 결과 발행 시각(sent_monotonic_s) 기준8.644 FPS. 동일 창의 보존된 입력 시각(nn_timestamp_s) 기준9.308 FPS.
- 이전 검증 스크립트 output_fps는 입력 시각 기준이었다. 대기열이 성장하면 출력 처리량보다 높게 표시되므로 이제 실제 발행 시각을 사용하고 input_clock_fps를 별도 기록한다. 이전 보고서의 숫자를 소급해 새 측정값으로 바꾸지 않는다.
- 카메라 캡처/주입 시각부터 텔레메트리 발행까지 정상 실행 평균1215ms, P95 1641ms. PC 송신 전의 파일 디코딩과 PC 화면 표시 지연은 포함하지 않는다. 이 수치를 순수 모델 추론 시간이라고 부르지 않는다.

## 단계별 계측

가벼운 타이머를 실제 콜백 내부에 넣고180개 PC 결과 시퀀스에 맞춰 집계했다. 계측 실행의 입력 시각 기반 FPS8.84는 정상 실행 속도로 사용하지 않는다. 타이머/JSON 저장도 부하를 더하므로 아래 숫자는 계측 시 비용의 추정치다. P95는 정렬 후 floor(0.95×(n-1))번째 값이다.

|---|---:|---:|---|
| 후처리 전체 |119.6|164.6|아래 경계/렌더링 등 포함|
| 경계 추적 |66.0|90.2|ImageBoundaryTracker.update|

후처리 내부 항목은 전체에 포함되고 별도 노드는 병렬 실행되므로 모든 행을 더하면 안 된다. 경계 추적은 전체 후처리의 약55%, 결과 렌더링은 약20%다. 기존 HEALTH bev_draw_ms는 bev_finished-boundary_finished로 정지선 검출까지 포함한다. 이번 타이머는 BEV를 별도로 구분했다.

전처리 종료→후처리 시작은 계측 평균1199ms였으나 NN 입력/출력 대기열과 프레임 동기화가 포함된다. 순수 가속기 시간은 미분리 상태다. CPU 전체 사용률의 단회 샘플11.3%(6코어), 주요 온도 약36~40℃. 이 샘플만으로 단일 스레드/GIL 병목을 배제하거나 열 스로틀링 유무를 확정하지 않는다.

## 개선 우선순위

1. **동일 검출 결과를 유지하는 경계 계산 재사용**: 반복 polyfit/최소제곱의 기저행렬·공통 행·후보별 적합 결과 캐시 검토. 정밀 cProfile에서는 polynomial.polyfit 약205회/프레임 관측. 후보 수/품질 임계값부터 줄이지 않고 동일 입력의 계수·상태 동등성부터 검사한다. masked-array 관련 호출도 많았으므로 실제 마스크 유효성/형을 확인한 뒤 중복 변환을 줄일 수 있는지 검토한다.
2. **RGB 변환·렌더링 재사용**: 현재 preview.getCvFrame을 경계/정지선/결과에 반복 호출한다. 프레임당 한 번 디코딩해 읽기 전용 공유할 수 있는지 확인한다. 마스크 확대/색상 혼합, 텍스트 그리기 비용도 비교한다. 공유 배열을 그리기로 변형하는 부작용은 회귀 검사한다.
3. **PC 입력의 무효 Depth 표시 비용**: PC 영상은 Depth가 항상0이므로 검정 미리보기의 색상 변환/배열 생성 재사용을 검토한다. 실제 카메라 Depth 처리와 구분하고 타임스탬프·시퀀스는 매 프레임 새로 부여한다.
4. **지연 관리**: 큐/동기화의 크기·blocking·프레임 나이를 계측하고 최신 프레임 처리 정책을 검토한다. 큐 축소가 처리 능력을 높이지는 않으며 입력/NN/Depth 시퀀스 정합을 깨지 않도록 한다. 동일 장면에서 p50/p95 지연과 누락률도 함께 평가한다.
5. **모델/정밀도 변경은 뒤로**: 우선 CPU 후처리를 줄인 뒤 NN 단독 throughput/latency를 따로 측정한다. 해상도 축소나 INT8 변환은 정확도 영향과 별도 보정 검증이 필요하다.

10FPS 개선 여지는 있지만 아직 최적화 전후 검증을 한 것은 아니다. 제안 목표는 후처리 평균80ms 이하, P95 100ms 이내와 지연 감소이며 달성을 보장하지 않는다. 같은 프레임 반복 출력으로 FPS만 높이는 방법은 제외한다.
