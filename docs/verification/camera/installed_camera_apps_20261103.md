# CAM01 AI/RGB 사전 설치 전환 (2026-11-03)

## 목적과 변경

카메라 연결 시 `oakctl app run`으로 개발 앱을 다시 빌드하던 경로를 제거했다.
AI/RGB를 각각 `.oakapp`으로 빌드·설치하고, 멀티뷰는 설치된 앱 ID에 대해
`app start <ID> --enable false`와 `app stop <ID>`만 실행한다.

| 모드 | 앱 식별자 | 버전 |
|---|---|---|
| 인식·검증 | `com.qsentech.oak4-yolopv2-standalone` | 0.33.2 |
| 6대 녹화 CAM01 RGB | `com.qsentech.oak4-rgb-only` | 0.1.2 |

대상은 CAM01 `1142227768 / 192.168.201.2`다. 설치 시
`--start false --enable false --keep-others`를 사용한다.
멀티뷰 시작 시 자동 연결을 하지 않고, 기존 `--auto-connect`도 무시한다.
개발 앱 ID(전체 0)는 설치 앱으로 인정하지 않는다. 패키지가 없거나 중복이면
시작 전 오류를 표시하며, 자동 빌드·설치로 우회하지 않는다.

반대 모드의 프로젝트 앱과 이전 개발 앱만 중지하고, 다른 식별자의 앱은 변경하지 않는다.
앱 소스를 수정한 뒤에는 별도 빌드·재설치가 필요하다.

## 검증

### 패키지 축소

Python 3.12.11 slim-bookworm 기반에 필요한 런타임을 설치한다.
컴파일 의존성은 같은 RUN 레이어에서 설치 후 제거하며 pip/apt 캐시,
정적 Python 아카이브·헤더와 NumPy 테스트 데이터를 제외한다.
AI는 사용 중인 person 320 모델만 포함하고 미사용 140MB 모델·테스트·분석 도구는
배포에서 제외한다. 로컬 모델 원본은 삭제하지 않는다. 두 패키지 모두 `--optimized`로 빌드했다.

| 패키지 | 최초 크기(bytes) | 최종 크기(bytes) | 감소 |
|---|---:|---:|---:|
| RGB | 1,385,726,464 | 820,817,408 | 40.77% |
| AI | 1,731,449,856 | 995,737,600 | 42.49% |

합계 1,300,621,312 bytes 감소. 수치와 SHA-256은
`artifacts/rgb_only_20261103/lean/package_comparison.json`에 기록했다.

- 전체 회귀 테스트: 325개 통과.
- 추가 설치 대기 상태(`ready`) 처리 테스트 통과.
- 최종 패키지: `artifacts/rgb_only_20261103/lean/*.oakapp`.
- 장치 전환·최종 상태 증거: `artifacts/rgb_only_20261103/installed_apps_report.json`.
- 장치 설치 및 실제 영상 검증 통과: RGB 1920×1080, AI 결과 960×540.
- RGB 상태 응답까지 6.46초, AI 영상 포트 준비까지 24.67초 측정(각 1회, 보장 시간 아님).
- 설치 앱을 `start`/`stop`으로 전환했으며 연결 과정에서 빌드하지 않았다.
- RGB 앱 ID: `daf6e137-7136-4186-968a-666620a3eb81`.
- AI 앱 ID: `bcc20cd0-0c3a-4b30-bfc1-b9701478b41a`.
- 검증 후 두 설치 앱과 기존 개발 앱 모두 `stopped`, `enabled=false` 확인.
- 검증을 통과한 축소본은 유지하고 이번 작업에서 생성한 큰 원본·중간 패키지는 정리했다.

ROS 노드·토픽·TF는 이 변경 범위에 없으므로 ROS 빌드와 토픽 Hz 검증은 수행하지 않는다.
실제 6대 동시 녹화 FPS 검증과는 별개의 CAM01 앱 설치·전환 검증이다.

## 중지 후 PC 재접속 종료 (2026-11-03)

앱 중지 버튼은 장치 명령을 보내기 전에 PC의 RGB/인식/TOP/Depth 수신기에
모두 종료 신호를 보낸다. 상태 조회로 외부 중지가 확인된 경우도 동일하게 종료한다.
RGB 녹화 앱 중지는 별도로 확인하며 인식 수신기와 분리한다.
알 수 없는 상태·일시적인 상태 조회 실패는 중지 확정으로 취급하지 않는다.
진행 중인 OpenCV open/read가 끝난 뒤 자원을 해제하고 재시도 루프로 돌아가지 않는다.
다음 명시적 연결에서는 새 수신기를 생성한다. PC 프로그램 수정이므로 멀티뷰 재시작 후 적용된다.

- 전체 회귀 테스트 332개 통과.
- 실제 FFmpeg + 로컬 connection refused 상황에서 수신기 4개를 두 차례 검증했다.
- 첫 중지 후 접속 호출 수 8→8, 수동 재연결·두 번째 중지 후 16→16으로 추가 시도 없음.
- 상세 증거: `artifacts/rgb_only_20261103/native_receiver_stop_report.json`.

### 2026-11-04 대기 상태 자동 조회 로그 수정
- 수신을 시작하지 않은 대기 상태에서는 자동 앱 상태 조회를 생략한다. RGB 연결 준비 중에도 자동 조회를 생략한다.
- 연결 후 자동 상태 감시는 유지하며 poll 진행/종료 반복 로그는 출력하지 않는다. 수동 명령의 10초 진행 로그는 유지한다.
- 검증: test_console_log 9개, test_receiver_stop 6개 통과. 실제 장치 연결은 이번 수정에서 실행하지 않음.
