# 스켈레톤 장기 유지와 반대편 커브 점진 반영

날짜: 2026-11-05. 버전: 0.33.4. 사용자 요청: 한쪽 스켈레톤이 사라져도
이전 형상을 유지하고 반대편 커브를 점진적으로 반영하며 full 모드로 배포한다.

## 변경

- full 모드의 최종 형상은 관측 스켈레톤을 320×180의48개 고정 행에 표본화한 점들이다.
  후보 품질 검사를 위한2차식은 유지하지만, 표시할 때 이를 다시2차식으로 덮어쓰지 않는다.
- 1.5초 후 경계 삭제, 양쪽0.6초 삭제, 반대편 보조3초 만료를 제거했다.
  마지막 관측 형상은 관측이 끊겨도 남는다. 처음부터 관측되지 않은 선은 생성하지 않는다.
- 소실 시 자신의 형상과 반대편의 기준 형상을 함께 보관한다. 목표는
  `소실 시 자기 형상 + (현재 반대편 형상 − 소실 시 반대편 형상)`이다.
  반대편의 절대 형상을 복제하거나 고정 폭으로 새 선을 만들지 않는다.
- 반대편 변화량은 관측 구간에서2차식으로 추정하여 위치·방향·커브 변화로 반영한다.
  소실 경계에 반영하는 이동은 시간상수0.4초와 전체 지지 구간 최대20px/s로 제한한다.
  직접 재검출 보정은 최대80px/s이며 확인 대기·후보 대응 검사를 유지한다.
- 원래 스켈레톤의 국소 굴곡은 이력에 남기고 보정 변화량만 더한다.
  서로 다른 좌우 원래 곡률을 강제로 같게 만들지 않는다.
- 반대편 관측이 불안정하거나 지지 구간이 부족하면 현재 형상을 그대로 유지한다.
  양쪽이 사라지면 두 형상을 유지한다. 교차를 유발하는 갱신은 이전 유효 쌍을 유지한다.
- 기억한 형상은 실제 관측으로 재입력하지 않는다. 마지막 관측 시각·관측 지지·폭 학습을
  갱신하지 않고 신뢰도는 계속 감소한다. 유지된 선이 최신 관측이라는 뜻은 아니다.
- 입력/미디어 epoch, 시간 역행·1초 초과 입력 단절, 해상도 변경·장면 전환은 초기화한다.
- RGB와 TOP은 동일한 추적 점을 직접 그린다. 현재 관측 지지가 있는 구간은 자홍색,
  유지·커브 보정 구간은 노란 점선이다. 관측 컨투어 테두리는 별도 표시 옵션이다.
- 텔레메트리 `boundary_model=persistent_skeleton`, `image_geometry=tracked_skeleton_samples`.
  `image_curve_degree=null`이며 기존 계수 필드는 최소제곱 근사임을 명시한다.
- 카메라 앱과 새 멀티뷰의 기본 처리 모드를 full로 변경했다. 기존 멀티뷰에서도
  전체 후처리 체크와 저장된 `full_processing=true`를 확인했다.

## 검증

전체 회귀359개 통과(WSL Ubuntu-22.04,58.231초).
장기 한쪽/양쪽 소실,3초 이후의 지속 커브 전달, 폭 학습 없는 전달,
좌우의 다른 초기 곡률 보존, 비다항식 스켈레톤 상세 보존, 장기 소실 뒤 재검출 상한,
직접 스켈레톤 렌더링·TOP 미관측 영역 검정 및 strict JSON 전송을 검사했다.
로그: `artifacts/persistent_skeleton_20261105/tests_final.log`.

기존0.33.3 실행 소스가 Git 기준과 일치함을 확인하고 백업 후4개 파일을 단계 배포했다.
백업: `/app/deploy_backup_88ca3887a9`. 최종 패키지 검증 전의 임시 실행 검사이다.
실제 녹화 영상을 PC에서 카메라로 보내 모델 추론·스켈레톤 추적·렌더링을 수행했다.
마스크 소실이나 가짜 관측을 주입하지 않았다.

단계 실행 자료 `artifacts/persistent_skeleton_20261105/stage_road/`:

- 수집305프레임 모두 `persistent_skeleton`.
- 미검출 최대 유지27.700675초,1.5초 초과 유지185프레임.
- 반대편 커브 반영99프레임, 그중 미검출3초 이후70프레임.
- 미검출 구간 최대 이동 속도13.6277px/s 미만,20px/s 상한 위반0.
- 실제 수집된 원본 구간은120초부터166.2초까지이며 요청한170초까지는 도달하지 않았다.
- 재시작·전송 오류 없이 실행됐다. RTSP는 초기에 수신 지연이 있었으므로
  최종 설치본 검증에서는 추론 프레임 준비 후 스트림을 수집한다.

## 한계

유지 표시는 최신 관측이 없는 기억 형상이다. 반대편도 보이지 않으면 움직임을
추측해 누적하지 않고 형상을 유지한다. 차량 이동·회전 센서 기반 예측이 아니며
정답 차선 대비 정확도나 실차 제어 안정성을 보장하는 검사는 아니다.
값의 단위는320×180 영상 px이며 실제 거리 단위가 아니다.
후보 선택은 여전히2차식 잔차·방향·지지 구간 검사를 사용하므로 복잡한 차선의
최초 검출 자체가 개선됐다고 주장하지 않는다.

## 최종 배포

첫0.33.4 패키지를 설치하고 부팅 직후 `full/persistent_skeleton`을 확인했다.
최종 설치본의 추적 소스5개는 패키지 해시와 일치했다.
Windows 실제 녹화 재검사(`final_windows`)는333프레임, 최대13.400139초 유지,
커브 보정138프레임, 미검출 이동 최대20px/s, 상한 위반·시퀀스 불일치·오류0이었다.
다만 RGB 영상에 매크로블록 깨짐이 있어 좌표 검사 통과만으로 표시 정상이라 판단하지 않았다.
WSL 수신은0프레임으로 실패했으며 실패 보고서도 `final_road`에 보존했다.

RTSP 재접속을 위해 이전 미디어 콜백의 세대를 구분하고, 손상된 GOP는 다음 IDR부터
SPS/PPS와 함께 다시 시작하도록 수정했다. 인코더는20프레임마다 키프레임을 생성하며
B프레임을 사용하지 않는다. 디코더 초기화·큐 초과 복구·이전 콜백 격리·재연결 회귀4개 통과.
수정 후 단계 검사 `rtsp_keyframe_road`에서269프레임, 최대27.699801초 유지,
반대편 보정87프레임(3초 이후74), 최대11.719568px/s, 상한 위반0을 확인했다.
실제 도로와 왼쪽 노란 점선이 정상 표시된 JPG도 확인했다.
이 검사에서는 초기 수신 지연과 재접속(RGB1/TOP3)이 남았으므로 연속 수신 보증은 아니다.

정지된 이전 앱을 보관해도 유일한 실행 앱이 있으면 멀티뷰가 그 앱을 선택한다.
모두 정지되었거나 둘 이상 실행 중이면 기존의 모호성 오류를 유지한다.
해당 회귀13개 통과. 이전0.33.3 삭제는 복구 앱/전용 저장소의 영구 삭제라는 자동 승인
검토의 거부로 수행하지 않았다. 새0.33.4는 별도 앱으로 실행한다.

전송 수정까지 포함한 최종 패키지를 재빌드·설치했다.
