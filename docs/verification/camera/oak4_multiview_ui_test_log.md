# OAK4 Windows 멀티뷰 UI 검증 기록

- 검증일: 2026-10-15
- 대상 파일: `tools/oak_recorder.py`
- UI 기준: 사용자 확정 `멀티뷰`

## 1. 화면 구성

```text
┌──────────────────────┬──────────────────────┐
│ 원본 RGB             │ 인식 결과            │
├──────────────────────┼──────────────────────┤
│ RGB 정렬 Depth       │ BEV · 가상 중심선    │
└──────────────────────┴──────────────────────┘
```

- 원본 RGB와 인식 결과는 기존 RTSP 프레임을 동시에 표시한다.
- Depth와 BEV는 아직 PC 영상 출력이 없으므로 연동 상태만 표시한다.
- 하단에는 장비 연결, 녹화 대상 선택, 녹화 시작·중지 및 저장 기능을 배치한다.

## 2. 검증 결과

| 항목 | 결과 | 근거 |
| --- | --- | --- |
| Python 문법 | 통과 | `py_compile tools/oak_recorder.py` |
| Tk 창 생성 | 통과 | 숨김 창에서 `RecorderApp` 생성 성공 |
| 멀티뷰 패널 | 통과 | `rgb`, `yolopv2`, `depth`, `bev` 4개 확인 |
| 최소 창 크기 | 통과 | `1040x760` 설정 확인 |
| 실제 RGB/결과 영상 표시 | 장비 검증 필요 | OAK 로그인 재인증 필요 |
| Depth/BEV 영상 표시 | 후속 구현 필요 | PC-facing 출력 미구현 |

## 3. 회귀 영향

- `CaptureSource`, RTSP URL, MP4 writer 및 저장 파일명은 변경하지 않았다.
- 녹화 대상은 기존과 동일하게 RGB와 YOLO 결과 두 스트림이다.
- 단일 미리보기 선택 라디오 버튼은 멀티뷰에서 불필요하여 제거했다.

## 4. 판정

멀티뷰 UI 기본 구조와 위젯 생성은 검증 완료했다. 실제 영상 연결 상태의 화면 배치와
프레임 갱신은 카메라 재인증 후 실장비로 확인해야 한다.
