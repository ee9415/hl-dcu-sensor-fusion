# 0.33.3 카메라 배포 및 실제 영상 검증

날짜: 2026-11-05. 대상: CAM01 OAK4 `1142227768 / 192.168.201.2`.

## 요청과 기준

사용자 요청으로 커밋 `bc9fbfd`의 0.33.3을 패키지로 빌드·설치하고 실제 영상에서
왼쪽 경계의 미검출 전환을 검사한다. 합성 마스크 주입 결과와 구분한다.
실제 녹화 영상은 PC에서 전송하고 추론·컨투어 추적·RGB/TOP 렌더링은 카메라 앱이 수행한다.

배포 전 설치 AI 앱은 0.33.2, 앱 ID `bcc20cd0-0c3a-4b30-bfc1-b9701478b41a`이며 실행 중이었다.
입력은 PC, basic 모드, lane_score 0.1, 컨투어·경계 표시 상태였다.
이번 기능은 full 모드에서만 활성화되므로 검증 시 full/normal/경계 표시로 전환한다.

기존 0.33.2 설치 패키지는 `artifacts/rgb_only_20261103/lean/`에 롤백용으로 보관한다.
기존 RGB 앱은 갱신 대상이 아니다. 자동 시작은 활성화하지 않는다.

## 빌드와 배포

```powershell
& 'C:\Program Files\oakctl\bin\oakctl.exe' app build apps/yolopv2_standalone -d 192.168.201.2 --optimized --output artifacts/deploy_0333_20261105
```

빌드 로그·입력 상태·실행 프레임·검증 영상과 텔레메트리는
`artifacts/deploy_0333_20261105/`에 보관한다. 패키지와 원본 영상은 Git에 포함하지 않는다.

## 검증 방법

`src/hl_camera_bringup/scripts/verify_deployed_contour.py`를 사용한다.

- 카메라 앱이 내보낸 `mask_contour_temporal` 텔레메트리와 RGB/TOP RTSP 수신을 확인한다.
- 왼쪽 observed/aligning/partial → held/inferred 전환에서 같은 지지 행의 최대 이동량을 계산한다.
- 연속 원본 프레임 사이의 미관측 이동이 `20px/s × dt` 이하인지 검사한다.
- 원본 프레임이 건너뛰면 중간 관측 여부를 알 수 없으므로 상한 판정 대상과 별도 집계한다.
- 입력 epoch·추적 초기화 구간을 연속성 성공 사례로 세지 않는다.
- RTSP 영상은 비동기 수신 및 10FPS 시각 샘플링이다. 텔레메트리와 정확히 동기화됐다고 주장하지 않는다.
- 검증 도구의 급변 검출·상한 위반·초기화 제외·프레임 건너뜀 처리는 4개 단위 테스트로 확인했다.

## 결과와 한계

### 초기 배포에서 확인하고 수정한 문제

- 기존 ID를 지정한 `app install --update`는 성공을 반환했으나 시작 시
  `Container does not exist` 오류가 발생하고 설치 목록에서도 AI 앱이 사라졌다.
  원인 확정 없이 반복 업데이트하지 않고 같은 패키지의 새 인스턴스 설치로 복구했다.
- 첫 full 실행에서 `TypeError: Object of type bool is not JSON serializable`로
  백엔드가 재시작됐다. 추적 진단의 NumPy 불리언 두 곳(`reset`, `accepted`)을
  Python bool로 변환했다. 엄격 JSON 직렬화 회귀를 추가하고 전체353개 통과(56.012초).
- 수정 커밋: `2403e34`. 실행 소스에 해시 검사·백업 후 동일 수정을 적용하고 먼저
  실제 영상으로 확인했다. 이 수정이 없는 최초 패키지는 최종 배포본이 아니다.
- 수정 소스의 SHA-256: `86aa3d1cde14b8964552acd6260e012301f570dad18c25b0fae8e195e31edfab`.

현재 결과에 따라 점진적으로 움직이는 것을 좌표로 확인했다.

자료: `artifacts/deploy_0333_20261105/road_120_160/`의 `report.json`, `frames.jsonl`,

카메라 직접 입력에서도 수정 후 추적 모델137프레임과 양쪽 RTSP 수신을 확인했다.
최초 검증 도구는 full 전환 전 NN 큐에 남은 basic7프레임까지 포함해 실패로 집계했다.
도구에서 전환 이전 접두 프레임만 별도 집계하고, 이후 basic 복귀·연결 종료는 여전히 실패로 처리한다.
