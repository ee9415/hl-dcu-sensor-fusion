# 주행 통로 연속성 수정

작성일: 2026-10-16

## 원인과 변경

기존 프레임별 주행 가능 영역 중점은 한쪽 확장에도 이동한다. 시간 필터만으로는
잘못 이동한 중점을 지연 추종할 뿐이므로 시간 필터 앞에 CorridorTracker를 추가했다.
동일 전방 거리의 좌우 경계를 이전 정상 통로와 비교한다. 한쪽만 확장되고 반대쪽은
안정적이면 이전 폭과 안정적인 경계로 중점을 재구성해 3차식을 피팅한다.
확장된 폭은 기준으로 학습하지 않는다. 양쪽이 같은 방향으로 움직여 폭이 유지되는
곡선은 기존 시간 필터로 전달한다. 점선은 원시 중점, 실선은 통로 보정+시간 필터 결과다.

양쪽 확장, 통로 축소, 겹치는 전방 구간 부족은 무효 측정으로 전달한다.
단일 경계 추정은 최대 3초이며 이후 기존 시간 필터의 짧은 hold를 거쳐 lost가 된다.
정상 경계가 돌아오면 재획득한다. 0.5초 초과 입력 공백은 기준을 초기화한다.
구조화 출력에 centerline_corridor_state를 추가했다. 기존 토픽/TF는 변경하지 않았다.

## 검증

- Ubuntu Python unittest 전체 22개 통과 (신규 6개).
- 좌/우 2 m 등가 확장이 20프레임 지속돼도 중심선 변위 0.03 m 등가 미만 확인.
- 양쪽 공통 이동, 합성 곡선 추종, 양쪽 확장/축소 거부, 추정 만료/복구,
  역순 타임스탬프와 입력 공백 테스트 통과.
- oakapp 0.7.0 카메라 배포 후 full pipeline running 및 RTSP 3개 시작 로그 확인.

## 제한 / 후속 검증

BEV는 기존 고정 호모그래피이며 보정된 실제 미터 단위가 아니다. 0.5 폭 변화,
0.3 안정 경계 기준은 개발용 BEV 스케일의 초기값이다. 차량 속도/요레이트로 경계를
운동 보상하지 않는다. 차선 마스크 융합, 실제 차로 식별, 주행 제어 안전성은 미검증이다.
첫 입력부터 넓어진 통로, 점진적 확장, 분기점, 큰 곡선/자차 이동에서는 추가 검증이 필요하다.
합성 테스트 통과가 실제 도로의 출렁임 해소를 보증하지 않는다.
