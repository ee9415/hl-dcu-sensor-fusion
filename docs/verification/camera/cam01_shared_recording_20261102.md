# 6대 녹화 탭의 CAM01 연결·독립 녹화

2026-11-02 사용자 요청 범위: 1번 OAK 4D Pro PoE 실제 연결 및 녹화.
2~6번 OAK-D Pro PoE는 계속 미구현이며 녹화 선택을 비활성화했다.

## 사용

1. 멀티뷰를 재시작하고 `6대 카메라 녹화` 탭을 선택한다.
2. `카메라 설정`에서 1번 IP를 확인한다. 현재 장치는 192.168.201.2.
3. `1번 연결`을 누르고 RGB가 연결될 때까지 기다린다. 기존 인식 탭에서 이미
   연결했다면 같은 수신기를 사용한다. 다른 IP로 중복 연결하지 않는다.
4. `녹화 설정`에서 저장 폴더/세션 이름/저장 해상도/FPS를 정한다.
   기본은 원본 스트림 해상도, 저장10FPS다. 설정은 실행 중에만 유지한다.
5. 1번을 선택한 상태에서 `1번 녹화 시작`, 종료할 때 `녹화 정지`를 누른다.
   별도의 파일 저장 버튼 없이 MP4를 마무리한다. 상태에 저장 경로/오류를 표시한다.

저장 폴더 아래 `<세션이름>_<시각>_<임의ID>/cam_01_rgb.mp4`, `session.json`이 생긴다.
MP4는 mp4v로 재인코딩한다. JSON에는 IP/수신URL/저장 크기·FPS/시각/프레임 수/
동일 수신 프레임 반복 횟수/오류를 기록한다. 새 녹화에는 별도 프레임·객체 CSV를
추가하지 않는다. 기존 인식 탭의 녹화/CSV 기능은 그대로 별도로 동작한다.

## 동작과 제한

- 기존 `CaptureSource`의 RGB 프레임을 읽는 독립 저장 스레드이며 수신기·기존
  writer를 소유하거나 정지하지 않는다. 두 탭의 파일 시작·정지는 독립적이다.
- 녹화는 입력이 camera인지 장치 TCP8558로 확인한 뒤 시작한다. PC 입력은 거부한다.
  녹화 중 메인 UI의 소스 변경/PC 전송 시작을 막고, 외부 소스 변경은 주기적 검사로
  감지하면 오류로 종료한다. 네트워크 상태 확인은 1초 주기이며 영상 프레임 단위
  소스 동기화를 보증하지 않는다.
- 연결 끊김/오래된 프레임/저장 지연/녹화 오류 시 writer를 해제하고 수신한 파일을
  마무리한다. 녹화 중 창 닫기도 마무리를 기다린다. 기존 세션 폴더를 덮어쓰지 않는다.
- 저장 해상도/FPS는 PC 재인코딩 설정이며 카메라 센서 설정을 바꾸지 않는다.
  수신보다 높은 FPS일 때 프레임 반복이 발생한다. 고정 FPS 파일이며 하드웨어 동기화,
  무손실 수신 프레임 보존 또는 장시간 목표 FPS 달성을 보증하지 않는다.
- 2~6번은 영상 수신/녹화를 시작하지 않는다. 기존 6대 OAK-D 프로그램도 실행하지 않는다.

## 검증

- 전체200개 검사 통과. 추가5개는 독립 MP4 및 크기/메타데이터 확인, 기존 writer
  불변, PC 소스 거부, 연결 끊김 시 재생 가능한 부분 파일, 기존 세션 보호,
  외부 소스 변경 중단을 확인한다.
- 실제 192.168.201.2에 새 탭의 연결 버튼으로 접속하여 두 탭을 동시에 녹화했다.
  새 CAM01 파일은1920×1080/10FPS/35프레임, 기존 탭 RGB는1920×1080/10FPS/82프레임,
  인식 결과는960×540/10FPS/38프레임. 세 파일 모두 디코딩 확인했다.
- 새 탭 정지 뒤 기존 RGB writer가 계속 프레임을 기록하는 것과 동일 수신 스레드/
  writer 유지 확인. 녹화 길이와 시작 시각은 서로 다르며 세 파일의 동기화 검증이 아니다.
- CAM0135프레임 중 동일 수신 프레임 반복14회로 기록되었다. 짧은 기능 검증이며
  지속 수신/녹화 성능 결과로 사용하면 안 된다.
- 최초 장치 RGB RTSP가 새 클라이언트에 프레임을 주지 않았다. 앱 백엔드만 재시작해
  복구했으며 카메라 코드/모델 재배포는 하지 않았다. 녹화 검증 후 새 RGB 재접속도 성공했다.
- UI 탭/팝업/최소 창 배치 및 기존 표시 설정 왕복·실패 복원 검사 통과.
