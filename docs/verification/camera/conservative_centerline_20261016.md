# 직선·완만한 곡선 및 매 프레임 변화 제한

작성일: 2026-10-16. oakapp 0.10.0.

## 변경 근거와 구현

사용자가 반복 관측한 S자 휨과 급격한 프레임 간 변화를 줄인다.
기존 한쪽 확장 억제와 적응 차수 선택은 유지한다. 기본 선택 최대 차수를 2로
제한하고 승격에 필요한 지속 시간을 0.8초로 늘렸다. 실험용 allow_cubic=True는
선택기 단독 테스트에만 사용하며 실제 노드의 최종 제한기는 항상 c3=0으로 만든다.

시간 필터의 가시 범위 복원/재초기화 뒤에 ConservativeCenterline을 적용한다.
이 뒤에는 재피팅하지 않는다. 초기화 이후 항상 같은 전방 0..40 개발 좌표에서
이전 출력과 후보의 차이를 비교한다. 2차식의 극점을 포함해 횡변위 최대값을
해석적으로 계산하고, 방향각·곡률 변화의 보수적인 상한도 계산한다.
전체 계수에 하나의 보간 비율을 적용하므로 부분 클리핑에 따른 꺾임이 생기지 않는다.

현재 개발용 설정:

- 횡위치 변화: 초당 0.5 개발 거리 단위 이하.
- 경로 방향각 변화: 초당 0.05 rad 이하. 차량 바퀴 조향각이 아니다.
- 곡률 변화: 초당 0.005 개발 역거리 단위 이하.
- 곡률 크기: 0.006 개발 역거리 단위 이하. 기울기 절댓값 0.20 이하.
- 프레임 허용량 = 변화율 × min(실제 프레임 간격, 0.1초).
- 미관측/시간 공백 때도 마지막 계수를 보존해 시간 경과로 큰 점프를 허용하지 않는다.
- 최초 유효 출력은 비교 대상이 없으므로 정적 형상 제한만 적용한다.
- 무효 관측은 유효로 꾸미지 않는다. 제한한 선이 현재 경계 안에 90% 미만 포함되면
  constraint_conflict로 무효 처리한다. 제한기 내부 상태는 서서히 후보를 향해 움직인다.

HEALTH의 input_rate_bounds는 이전 최종 출력에서 현재 제한 전 후보까지의 요구 변화율
상한이며, 원시 입력의 연속 프레임 변화율과 동일하지 않다. output_rate_bounds는 실제
최종 계수 변화의 상한이다. 비교 없는 프레임은 집계에서 제외한다.

## 검증 및 영향

Ubuntu unittest 40개 통과. 무작위 250프레임, 가변 프레임 간격/거리 범위,
3차 제거, 실제 atan 방향각 및 곡률 수식, 공백/무효/역순 입력, 직선 보존을 검증했다.
git diff --check 통과. 카메라 배포 및 RTSP 출력 확인.
ROS topic/TF/namespace와 드라이버는 변경하지 않아 ROS build/launch 검증은 수행하지 않았다.

1차 실영상: artifacts/centerline_conservative_20261016/result.mp4.
30.004초 294프레임, 연결 성분 분석 중심선 미검출 0, 위치 변화 p95 2px/최대 4px.
이 영상은 곡률 상한 0.02의 중간 설정이며 최종 설정의 결과로 혼동하면 안 된다.
6개 영상 표본의 단일 굽힘을 더 줄이기 위해 최종 곡률 상한을 0.006으로 낮췄다.

2차 실영상: artifacts/centerline_conservative_final_20261016/result.mp4.
30.052초 292프레임 중 도로 영상 대신 사슴 바탕화면이 약 18초간 나타났다.
미검출 238프레임(최장 220), 검출 구간 p95 3px/최대 4px.
도로가 돌아온 뒤 constraint_conflict로 재획득이 늦어지는 것도 확인했다.
이는 무소실 성공 사례가 아니며, 도로가 없는 구간과 재획득 지연을 모두 포함한다.

최종 도로 재검증: artifacts/centerline_conservative_road_20261016/result.mp4.
30.050초 292프레임, 중심선 미검출 0, 같은 영상 행의 위치 변화 p95 2.5px/최대 6px.
6개 표본에서 직선 또는 한 방향의 완만한 곡선을 확인했다. 최종 c3는 항상 0이며
2차식 곡률의 부호는 한 프레임 내에서 반전되지 않는다. 색상 검출 수치는 근사치다.
이전 버전 관측값 p95 8px/최대 48px보다 작지만 동일 영상 구간 비교는 아니다.
이후 장시간 로그에는 constraint_conflict가 다시 발생했다(01:45:49 UTC 10프레임,
01:45:54 UTC 5프레임, 01:46:04 UTC 31프레임). 무소실을 일반화하지 않는다.
01:45:59 UTC에는 c2=c3=0의 직선 복귀도 확인했다.
로그의 최종 변화율 상한은 부동소수점 허용 오차 내 설정 이하였고, 처리 FPS 약 9.9였다.
관측 점선과의 차이가 커지는 창도 있어 정답 경로 추종이나 차량 조향 검증으로 해석하지 않는다.

## 미확정 및 적용 제한

차량 휠베이스/최대 조향각/조향 속도는 사용자도 아직 모르는 상태다.
현재 BEV는 고정 호모그래피 개발 좌표이며 실거리 보정되지 않았다.
이 설정은 실제 차량의 조향 가능성이나 안전 주행을 보장하지 않는다.
곡선 단순화와 강한 변화 제한은 S자 휨을 억제하지만 실제 급커브 추종 지연을 만든다.
관측을 오래 잃었다가 복귀할 때도 지연이 발생할 수 있다. 없는 경로를 표시하거나
변화율 제한을 무시해 이를 감추지 않는다. 실제 주행 전 재획득 정책 검증이 필요하다.
시험은 모니터의 도로 영상을 카메라로 촬영한 것이며 실제 도로 주행 시험이 아니다.
과거 녹화와 동일 입력 비교가 아니므로 개선율을 계산하지 않는다.
