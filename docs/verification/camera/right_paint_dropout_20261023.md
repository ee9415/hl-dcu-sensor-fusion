# 보이는 오른쪽 흰색선 검출 탈락 추적

날짜: 2026-10-23. 운영 0.30.1 알고리즘 변경 없이 임시 sys.setprofile 기록기로
실제 update 입력/중간마스크/후보를10프레임 기록했다. 기록 종료 후 임시 모듈과
호출 래퍼를 제거하고 원래0.30.1 재배포, 실행 버전 확인. node diff 없음.

## 결론

오른쪽 가까운 흰색선 픽셀은 최종 paint 마스크에 존재한다. 그러나 해당 선을
추적한 점은10프레임 모두3개/세로4px로 끝난다. 후보의 존재와 곡선 승인 조건은 다르다.
이 장면에서 객체 제외가 이 가까운 흰색선3점을 없앤 것은 아니다.

## 실제 변수 (320×180 내부 좌표)

- 첫 프레임 밝기 threshold=206.3333,10프레임 범위206.3333~207.6667.
- 실제 밝은 선은 y174의 x204~205, y172의 x201~204, y170의 x199~201,
  y168의 x197~199, y166의 x195~197, y164의 x193~195에 남아 있다.
- seed 행은168,156,144,132로 고정되어 y170~174의 가까운 선은 시작 추적에서 사용하지 않는다.
- 선택 seed=(y168,x198), 연결점=(198,168),(197,166),(195,164).
- len(ys)=3,ptp(ys)=4. 승인 요구는 점10개 이상,세로20px 이상이므로 short 분기에서 탈락.
- y162,160,158,156,154의 가까운 연장 방향에는 최종 후보가 없다.
  해당 조사 띠에서는 white_lane_evidence 단계부터 후보가 없었다.
- y152에는 x176~178의 다른 조각이 있지만, last=164/value=195/slope=0이다.
  다음 검색 중심은195,gate=5+0.25×12=8이며 가까운 점178도 차이17이어서 연결되지 않는다.
- slope는4점이 모인 뒤에만 계산한다. 3점 뒤 끊겨 방향 추정 시작 전 탈락한다.
  기울기를 조기에 계산하는 것만으로 반드시 검출이 해결되는 것은 아니다.

## 마스크별 재실행 (첫 프레임)

| 단계 | 오른쪽 seed | short | 승인 후보 |
|---|---:|---:|---:|
| RGB/AI 흰색 근거 |23|5|17|
| 밝기 필터 추가 |10|7|3|
| 도로 마스크 추가 |3|3|0|
| 객체 제외 추가 |3|3|0|

도로 마스크 전 승인 후보에는 차량·표지판 등도 포함될 수 있다. 따라서 위 표만으로
도로 마스크가 정답 차선을 모두 지운다고 결론내리거나 마스크를 제거하면 안 된다.
단계 이미지에서는 가까운 실제 흰색선 일부가 도로/객체 마스크 후에도 남아 있음을 확인했다.
최종적으로는 짧은 조각의 연결과 지지 길이 부족이 해당 seed의 직접 탈락 원인이다.

## 수정 방향과 부작용

1. 실제 선 조각을 선분 단위로 검출하고, 최소 지지 길이와 방향의 불확실성을 함께 평가.
2. 시작 위치를 고정4개 행에만 의존하지 않도록 하되 후보 수 상한으로10 FPS 예산 유지.
3. 공백 연결은 이전 경계/선분 방향/도로 지지로 검증. 검색폭만 넓히면 차량 반사선으로
   넘어갈 수 있으므로 거리와 방향 일치 조건을 함께 사용.
4. 짧은 조각은 전체 경계 OBSERVED 승인보다 해당 관측 구간의 제한된 보정 근거로 사용.
5. 전역 밝기 기준을 낮추기 전에 국소 대비 단계와 실제 흰색선 띠의 후보 소실을 검증.
