# 중심선 시간 연속 추적 개선

날짜: 2026-10-16

## 변경 근거와 구현

기존에는 서로 다른 전방 거리의 배열 인덱스를 비교하고 3회 거부 후 큰 변화를
그대로 수용했다. 이제 공통 유효 거리에서 3차식을 평가하고 시간 기반 이득으로
보정한다. 기본 시간 상수 0.35 s, 급변 기준 0.65 m, 측정 보정에 의한 횡변화
상한 1 m/s, 유실 유지 0.3 s, 재획득 일관성 확인 0.3 s를 사용한다.
이 값은 고정 IPM 개발 좌표에서의 초기값이며 실차 튜닝·보정이 필요하다.

출력 계수로 BEV와 영상 곡선을 다시 생성하여 표시와 수치 결과를 일치시켰다.
관측 범위가 겹치지 않거나 0.5 s 초과 시간 공백이면 재획득 상태로 전환한다.
재초기화는 별도 상태로 표시하며 이 경우 이전 선과의 연속성을 보장하지 않는다.
HEALTH에 tracking_state, measurement_age_s, motion_compensated를 추가했다.
RGB 결과의 회색 점선은 원시 검출, 청록 실선은 추적, 주황 실선은 유지/예측이다.

속도와 yaw rate를 전달하면 일정 회전율 운동으로 이전 선을 현재 좌표로 변환한다.
좌표는 x 전방/y 우측, yaw는 우회전 양수이다. ROS 표준 yaw를 연결할 때 부호를
변환해야 한다. 현재 노드에는 CAN/IMU가 연결되지 않아 motion_compensated=false다.
센서 입력의 시간 동기화 및 미래 시점 예측 출력은 후속 통합 작업이다.
현재 구현은 신뢰도 가중 시간 필터이며 Kalman 공분산 추정기는 아니다.
주행영역 중심은 목표 차로/장애물 회피 경로와 다르며 도로 분기 선택은 미구현이다.

## 검증

WSL Ubuntu 22.04 Python 3.10에서 unittest 16개 통과, compileall 통과.
시험 범위: 지속 급변의 변화율 제한, 교대 이상치, 유실 만료, 재획득,
관측 범위 변화, 역순 timestamp, 장기 공백, 전진/회전 좌표 변환, 기존 거리 추정.
실제 연속 도로 영상에서 횡위치/곡률 흔들림과 반응 지연 개선량은 미측정이다.
차량 보정과 차량 운동 입력 없이 실제 조향 성능을 보장하지 않는다.

09:33 KST OAK 개발 앱 실행 후 새 HEALTH 상태 필드 확인. RTSP RGB 1920x1080,
결과 960x540, BEV 640x480 각각 30프레임 수신 성공. 연결 지연 포함 단기 시험으로
FPS 안정성 평가에는 사용하지 않는다. 현재 장면은 검출 0, 중심선 lost 상태이다.
detached 실행은 장비 failed 상태로 끝나 절대경로의 전경 실행으로 복구했다.
현재 개발 실행은 해당 oakctl 세션에 종속되며 자동 시작 설정은 변경하지 않았다.
