# 고정 시작점과 일정 폭을 갖는 BEV 경계

작성일: 2026-10-22 | 소스 버전: 0.20.0 | 장비 배포: 이번 변경에서 미수행

## 요구와 설계 결정

사용자 요청은 관측된 흰색선의 좌우 개별 추적에서, 항시 표시되는 고정 폭 주행 통로로
변경됐다. 기존 개별 유효성/소실/연관 거리/재획득 로직은 새 전략에 맞지 않아 제거했다.
흰색선의 RGB 대비 검출과 투영·그리기 함수는 보조 근거/출력용으로 재사용한다.

좌표는 x=전방, y=좌우이며 양쪽 모두 y=C0+C1*x+C2*x² 형식이다.
차량 가까운 x=0의 시작점은 다음과 같이 고정한다.

- 왼쪽 C0 = -차폭/2 - 왼쪽 여유
- 오른쪽 C0 = 차폭/2 + 오른쪽 여유
- 목표 수직 폭 W = 차폭 + 왼쪽 여유 + 오른쪽 여유

왼쪽 2차식은 시작 접선을 전방으로 고정(C1=0)하고 C2 후보를 탐색한다. 이렇게 해야
같은 전방 위치의 고정 시작점 간격 W를 시작점의 법선 폭과도 일치시킬 수 있다.
그 곡선의 정확한 법선 오프셋 표본에서 오른쪽 C0를 고정하여 별도 C1/C2를 구한다.
우측 계수는 좌측과 같게 강제하지 않는다. 중심선 계산/표시/제어 출력은 없다.

일정 거리 오프셋은 일반적으로 정확한 2차식이 아니므로, 실제 피팅된 두 곡선의
법선 교점 거리를 측정하고 허용 폭 오차를 초과하는 후보는 제외한다. 기본 허용치는
0.08 개발 단위. 곡선 교차, BEV 좌우 범위 이탈, 오프셋 전방 좌표 역행도 제외한다.
검사는 유한한 81개 전방 표본에서 수행하며 연속 곡선 전체에 대한 해석적 보장은 아니다.

## 공간 탐색 및 시간 연속성

81개 C2 후보 중 유효 기하만 유지한다. 각 후보의 전방 81개 단면에서 좌우 경계 사이
25점을 도로 마스크와 비교한다. 모든 단면이 지지 임계치(기본 90%)를 만족하면
폭 확보 후보로 취급한다. 주변 0.3 개발 단위의 추가 도로 여유, 약한 표식 근거,
완만한 곡선/이전 곡선 선호를 함께 사용한다. 폭 확보 후보가 부족 후보보다 우선한다.

확보 후보가 없으면 전체 지지가 가장 좋은 방향을 선택하지만 폭을 줄이지 않는다.
시작점이 고정이므로 이미 차량 가까운 부분 자체가 좁다면 전방을 휘어도 전체 폭을
확보할 수 없으며 blocked를 유지한다. 급한 커브/S자/교차로 진로 선택은 이 단일
2차 곡선 후보군의 범위를 벗어날 수 있다. 이를 해결됐다고 주장하지 않는다.

표시 변화는 최대 횡이동 속도 설정으로 제한한다. 계수를 좌우 독립 보간하지 않고
보간한 좌측 C2에서 곡선 쌍을 다시 생성하여 폭/시작점을 재검사한다. 후보 경로가
가능하더라도 보간 중인 현재 표시 경로가 아직 부족하면 상태는 blocked다.
도로 인식이 없으면 마지막 쌍을 유지하며 최초 입력부터 없으면 고정 직선 쌍을 표시한다.
시간 역행/비정상 값은 형상을 유지하고, 유한한 시간 재시작은 다음 프레임의 기준으로 삼는다.

## 상태·CSV·설정 변경

- boundary_valid/좌우 유효성/pair_valid: 표시 가능한 기하이며 주행 승인 아님.
- tracking: 현재 표시 쌍이 도로 지지 임계치를 만족. 측면 상태 planned, 실선.
- blocked: 부족하거나 제한된 관측 범위. 양 경계 유지, 점선.
- held/invalid_timestamp: 미관측 또는 시간 오류. 경계 유지, 점선.
- corridor_feasible/clearance_sufficient: 확보 true, 부족 false, 미확정 null.
- 좌우 boundary_coefficients: [C0,C1,C2] JSON 배열. normal_width_error_dev와 road_coverage 추가.
- boundary_width_min/max_dev는 동일 전방 위치의 수평 폭이다. 커브의 법선 폭과 구분.
- 기존 중심선 CSV 칸은 호환성을 위해 disabled/빈 값 유지. CenterlineBEV 전송 이름 유지.

삭제 설정: observation_gate_m, max_missing_s, max_lane_gap_s.
추가 설정: max_curvature_coefficient=0.02, width_tolerance_m=0.08,
road_support_threshold=0.9. 차폭/여유/표시 거리/횡이동 속도 설정은 유지한다.
설정 파일 변경 후 앱 재시작 필요. 잘못된 설정은 명시적으로 실패한다.

## 검증 결과

호스트 전체 현행 unittest **22개 통과**. 삭제된 과거 알고리즘 테스트는 포함하지 않는다.
핵심 시험은 양방향 조밀한 최근접 거리로 폭 근사를 별도 검산하며, 각 계수로 표시
배열을 재구성하고 시작점 고정/양쪽 존재/프레임 이동 제한도 검사한다.

- 직선/좌우 커브: 고정 시작점, 좌우 다른 계수, 법선 폭 허용치 내.
- 도로 급확장/먼 흰색선: 경계 폭 유지.
- 전방 좁아짐과 좌/우 넓은 경로: 해당 방향 탐색 및 최종 통로 확보.
- 좁은 도로/전방 일부만 관측: blocked, 폭 유지, 양쪽 표시.
- 최초 도로 없음/장기 소실/비정상·역행 시간: 양쪽 표시 유지.
- 후처리 통합 및 TCP CSV 계수 배열/상태 직렬화, Depth·객체 기존 회귀 통과.
- UI/CSV/새 경계 모듈 py_compile 통과. 제거 모듈을 참조하는 활성 Python import 없음.

`verify_fixed_bev_boundaries.py`의 6개 합성 장면 BEV를 시각 검사했다.
기본 폭 2.4에서 좌/우 커브 최대 폭 오차 각각 약 0.000092/0.000033 개발 단위.
좁은 도로는 지지율 0.48/blocked, 도로 없음은 feasible null/held로 표시됐다.
호스트 계산부 중앙값 약 7.6ms, p95 약 11.5ms이며 AI/RGB 처리·장비 전체 FPS는 아니다.

재현: 번들 Python에서 `-m unittest discover -s apps/yolopv2_standalone/tests`
(PYTHONPATH를 해당 앱 폴더로 지정), `src/hl_camera_bringup/scripts/verify_fixed_bev_boundaries.py`.

## 미검증 범위

이번 사용자 요청 범위는 코드 분석/정리/전략 변경이며, **카메라 배포나 실시간 멀티뷰
재검증은 수행하지 않았다.** 장비의 현재 실행 버전도 이번 턴에서 조회하지 않았다.
BEV는 기존 미보정 개발 투영이다. `_m` 설정이 실제 미터와 일치하는지, 실차 환경에서
고정 시작점 위치가 적절한지는 보정 후 확인해야 한다. 기본 시작점은 설정으로 결정되며
사용자가 그린 이미지의 픽셀 위치를 자동 추출/고정하는 기능은 아니다.
이 도로 마스크 지지는 충돌 회피/조향 제어의 안전성 검증이 아니다.
비 ROS2 경로 변경이므로 colcon/TF/topic 검사는 해당하지 않는다.

변경 이력: 2026-10-22 — 0.20.0 전략 전환, 구형 코드 제거, 호스트/합성 검증.
