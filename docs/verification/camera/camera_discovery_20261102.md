# 카메라 찾기 (2026-11-02)

멀티뷰의 `6대 카메라 녹화 → 카메라 설정 → 카메라 찾기`에서 OAK4와 OAK-D PoE를
읽기 전용으로 검색한다. 검색 중 UI를 유지하며 앱 시작/녹화/카메라 파이프라인 생성은
하지 않는다. 결과의 종류/IP/장치ID/상태를 선택해 CAM01~06 설정에 적용할 수 있다.
설정 적용 후 연결 버튼을 별도로 눌러야 실제 연결된다.

- OAK4: oakctl device list --all --format json.
- OAK-D: 지정된 DepthAI2 Python에서 일반 장치와 부트로더 장치 목록을 검색해 중복 제거.
- WSL에서 OAK-D 결과가 없으면 Windows 네이티브 검색을 보완 실행한다. 현재 Windows
  Python3.12와 artifacts/oakd_windows_sdk의 DepthAI2 모듈을 사용한다. 다른 환경에서
  이 경로/SDK가 없으면 경고를 표시하며 IP 직접 지정은 계속 사용할 수 있다.
- 검색 실패는 다른 종류의 검색 결과를 지우지 않고 부분 오류를 함께 표시한다.
- OAK4는 CAM01에, OAK-D는 CAM02~06에 적용한다. 같은 IP/ID 중복 배정, 사용 중인
  OAK-D 수신기 설정 변경, 녹화 중 설정 적용을 막는다. 기존 값은 명시적 적용 시에만 변경.
- SDK 검색은 장치 계열을 보여주며 세부 제품명이 OAK-D Pro인지 장비 정보를 읽어
  별도 확정하는 기능은 아니다. 검색된 장치 상태와 실제 RGB 수신 성공은 구분한다.

실제 검색 결과:

| 계열 | IP | 장치 ID |
|---|---|---|
| OAK4 | 192.168.201.2 | 1142227768 |
| OAK-D / DepthAI2 | 192.168.201.5 | 19443010E131771300 |

두 장치가 통합 검색에서 발견됐고 경고는 없었다. 실제 Tk 버튼으로 검색하는 동안
UI176회 갱신, CAM02 설정 자동 입력, 중복 CAM03 배정 거부, 연결 자동 시작 없음 확인.
설정 팝업은784×556. 근거: artifacts/camera_discovery_20261102/actual_discovery.json,
gui_report.json, verify_gui.py.

멀티뷰를 재시작해야 새 버튼이 보인다. 검색 자체는 실행 중인 장치·녹화를 변경하지 않는다.
