# 연결 사다리꼴 구간 구현 및 검증 — 2026-10-22

## 범위

사용자가 제안한 기본 사다리꼴, 전방 구간 분할, 커브에서 구간 이동, 외곽 흰색선 검색을
함께 구현했다. 보완점만 기존 추적기에 덧붙인 변경이 아니다. 로컬 앱 버전 0.27.0.
카메라에는 배포하지 않았으며 0.26.0을 유지한다.

| 요청 | 구현 |
|---|---|
|기본 영역·직선 유지|설정된 사다리꼴의 좌우 직선, 8개 단면/7개 구간 초기화|
|커브에서 구간 이동|구간별 외곽 흰색선 관측과 도로 마스크의 제한된 공통 횡이동|
|영역 가장자리 검색|예상 외곽 주변 좁은 창에서 여러 행의 흰색 지지 평가|
|연결 틈 방지|인접 사다리꼴이 동일 꼭짓점 공유, 방향 변화 패널티와 형태 보존 보간|
|도로가 넓어져도 폭 유지|도로 마스크는 공통 이동만, 양쪽 흰색선 관측에서만 느린 폭 학습|
|소실·재등장|노드별 움직임 보상 이력·이전 폭/반대편 추론, 연속 후보 확인·보정량 제한|
|중심선 제외|좌우 경계와 선택적 가로 구간선만 표시, 중심선 텔레메트리 비활성|
|2m 구간|현재는 원근에 따라 영상 행 간격을 줄인 구간. 보정 없는 실제 2m 주장은 하지 않음|

## 변경 파일

- `apps/yolopv2_standalone/trapezoid_boundaries.py/json`: 새 모델·설정.
- `yolopv2_node.py`: 활성 추적기 교체. 기존 ImageBoundaryTracker는 비교용으로 보존.
- `lane_boundaries.py`: 구간 가로선 및 국소 관측 강조. 정지선은 기존 인터페이스로 연결.
- `tools/frame_csv_logger.py`: 구간 꼭짓점/노드 상태·신뢰도/거리 보정 여부 기록.
- `src/hl_camera_bringup/scripts/verify_trapezoid_tracker.py`: 동일 입력 A/B 오프라인 검증.

## 검증

전체 unittest 63개 통과: 기존52개(노드 통합은 새 모델 기대값으로 갱신) + 새11개.
직선·커브·도로 확장·도로에 따른 공통 이동·한쪽 관측·15초 소실·복귀 보정 제한·원거리
표시 제한·차량/횡선 억제·공유 꼭짓점 보간·설정/타임스탬프 초기화를 검증했다.
ROS build/launch/topic/TF는 standalone 앱 변경으로 적용하지 않았다.

동일 120프레임 합성 시퀀스(직선→커브→소실→재등장), 320x180 기준:

|항목|기존 0.26 추적기|새 구간 추적기|
|---|---:|---:|
|평균 위치 오차|0.680px|0.823px|
|프레임 평균 오차의 최댓값|1.267px|1.801px|
|출력 소실 프레임|0|0|
|로컬 업데이트 평균|16.47ms|9.18ms|
|로컬 업데이트 p95|21.87ms|10.65ms|

이는 WSL/개발 PC의 합성 입력 수치이며 카메라 종단 10 FPS 검증이 아니다.
새 방식의 정확도가 개선됐다는 결과도 아니다. 단순 합성에서는 기존 오차가 더 작다.

자료: `artifacts/trapezoid_0270_offline/report.json`, `synthetic_comparison.jpg`.
저장 RGB45장도 동일 입력으로 비교해 `rgb_only_diagnostic.jpg`에 기록했다.
이 자료에는 동기화된 NN 도로 마스크/객체 박스가 없어 하단 ROI로 대체했고 입력 손상이 있다.
따라서 실제 도로 마스크 기반 정확도/안전성 평가로 사용할 수 없다. 초기 영역과 실제
도로 위치가 다르거나 객체 마스크가 없으면 오검출·초기 정합 지연이 남을 수 있다.

## 미확정 및 후속 검증

- 카메라 실제 10 FPS, 깨짐 없는 동기화 영상과 프레임별 정답 대조: 미검증.
- 실제 2m 분할: 카메라 내부/외부 보정·노면 모델·피치 변화 처리가 필요.
- 신뢰도는 휴리스틱이며 실제 차선 정답 확률이 아님. 기본/유지 영역은 0 신뢰도도 표시한다.
- 도로 마스크의 오검출/객체 가림, 급커브, 언덕에서 범위 제한 및 초기화 추가 검증 필요.
- 이번 변경은 코드 구현과 로컬 검증까지이며 배포 성공으로 보고하지 않는다.
