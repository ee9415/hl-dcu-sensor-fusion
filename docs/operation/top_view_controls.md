# TOP 뷰 조절바

멀티뷰를 다시 실행하고 **표시 설정 → TOP 뷰 원근 조절**을 연다.

| 조절 | 범위 | 의미 |
|---|---|---|
| 상단 벌어짐 보정 | -30~100 | 0은 기존 변환. 양수는 위쪽 폭을 좁게, 음수는 넓게 조정 |
| 앞쪽 도로 포함 범위 | 0~100 | 0은 기존 영역. 높일수록 원본의 위쪽 도로를 더 포함 |

조절바를 놓거나 숫자를 입력하고 Enter 또는 **적용·저장**을 누른다. 연결 전에도 PC 설정에 저장되며 앱을 다시 열면 복원된다. **기본값 복원**은 두 값을0으로 되돌리고 저장한다. 기존 사용자 설정은 그대로 유지한다.

영상 연결 시 저장된 값을 카메라에 전송한다. 연결된 상태에서 변경하면 비동기로 적용하며, 원본 입력·차선 추적 이력은 초기화하지 않는다. 저장과 장치 적용 상태를 구분한다. 실패해도 PC에 저장한 값은 유지되며 연결/코드 버전을 확인하고 다시 적용한다.

처음에는 벌어짐 보정20~40, 앞쪽 범위30~50 정도에서 조금씩 조정할 수 있다. 이는 제안 시작값이며 실제7분53초 장면에서 검증한 보정값은 아니다. 도로 영상과 분홍 곡선에 동일한 투영을 사용한다. 차선 검출·추적 좌표나 도로 폭 학습 자체는 바꾸지 않는다.

## 카메라 연결 후 준비

이 기능은 PC 멀티뷰와 카메라 앱 양쪽 코드 업데이트가 필요하다. 기존 code11 카메라는 새 제어 명령을 지원하지 않는다. 실행 환경 패키지는0.33.10을 유지할 수 있다.

2026-11-10에는 하드웨어가 없어 배포하지 않았다. 다음 코드 묶음을 준비했다.

- 파일: artifacts/top_controls_20261110/code.zip (0.33.10-code12,84,991bytes)
- 장치 연결 후 저장소 루트의 CMD에서 앱 코드를 배포한다.

```bat
cd /d D:\git_hub\hl-dcu-sensor-fusion
python src\hl_camera_bringup\scripts\deploy_code_release.py deploy --app-id 61fbe0c1-ad26-42dc-93c4-a8d2b5191fce --bundle artifacts\top_controls_20261110\code.zip --output artifacts\top_controls_20261110\deployed.json
```

카메라 IP 기본값은192.168.201.2다. 달라지면 --device-ip 인자를 추가한다. 배포 후 멀티뷰를 다시 실행하고 영상 연결 후 값을 조절한다. 실제 처리 시각7분53초 전후의 TOP 폭과 추가 원거리 영역을 비교한다. PC 전송 위치와 출력 헤더 시각은 다를 수 있다.

## 구현과 오프라인 검증

- TOP 전용 원근 설정에서 하단 기준점은 고정한다. 앞쪽 범위는 원본 상단 기준 .62→.56, 해당 높이의 좌우 기준점은 기존 도로 광선을 따라 계산한다. 벌어짐 보정은 그 높이의 좌우 폭에 반영한다.
- 새 TCP top_view 명령은 두 값을 한 번에 검사하고 적용한다. 상태/프레임 메타데이터에는 top_view_spread, top_view_ahead, top_view_epoch를 기록한다. 기존 입력·처리 epoch 및 과거 프레임 설정은 유지한다.
- 전체 회귀413개 통과(65.620초). 기본값 동일성, 하단 고정/상단 축소 방향, 범위 검사, localhost 제어와 메타데이터 보존, 오프라인 저장/복원·기본값 복원을 검사했다.
- 실제 Tk 설정 창을 임시 설정 파일로 열어 저장·다시 읽기 및 조절바/버튼 배치를 확인했다. 카메라 호출0회. artifacts/top_controls_20261110/tests.log 및 ui_result.json 참조.
- 실장치 적용·영상 검증은 하드웨어 연결 후 수행해야 한다.
