카메라 기능 요구사항 및 인터페이스 정의서

과제명: 저속 특수목적 자율주행 PBV 플랫폼용 ROS2 기반 다중 카메라 AI 인지 소프트웨어 개발
용역명: PBV 플랫폼 AI 인식 소프트웨어 개발 용역
발주사: 주식회사 큐센텍
수행사: 보임테크놀러지 주식회사
적용 장비: Luxonis OAK-D Pro PoE 6대
문서 버전: v0.1 초안
작성일: 2026-11-25
문서 상태: 요구사항 및 인터페이스 검토용

1. 문서 개요
1.1 목적
6채널 카메라 AI 인지 소프트웨어의 기능 요구사항과 입출력 인터페이스를 정의한다. 개발·통합·시험·검수의 공통 기준으로 사용한다.
1.2 적용 범위
RGB·Depth 입력, 객체·차선·주행가능영역·정지선·신호등·신호색 인지, 객체 거리 산출, 연속 프레임 처리, ROS2 출력, 상태 진단 및 검수 방법을 포함한다.
차량 최종 주행 판단과 조향·가감속 제어는 차량 통합 시스템이 수행한다.
1.3 용어
카메라 ID: CAM01~CAM06 논리 식별자. MX ID: 장치 고유 식별자.
Timestamp: 입력 영상 또는 대응 인지결과의 기준 시각. Frame ID: 데이터 표현 좌표계.
관측 결과: 현재 영상에서 검출한 결과. 추정 결과: 이전 프레임 또는 다른 관측으로 보완한 결과.

2. 시스템 구성 및 카메라 역할
2.1 구성
OAK-D Pro PoE 6대, PoE 네트워크 장비, DCU 및 ROS2 소프트웨어로 구성한다.
영상·Depth 획득 → 전처리·AI 추론 → 인지결과·거리 생성 → DCU 수신·연속 프레임 처리 → ROS2 발행 → 차량 통합 시스템 수신.
카메라·DCU의 개별 기능 분담은 최종 구현에 따라 확정한다.
2.2 배치와 역할
CAM01: 전방 중앙 장착·전방 시야. 전방 객체, 차선, 주행가능영역, 정지선, 신호등·신호색.
CAM02: 좌측 전방 장착·좌측 후면 시야. 좌측면·좌후방 객체 및 사각지대.
CAM03: 우측 전방 장착·우측 후면 시야. 우측면·우후방 객체 및 사각지대.
CAM04: 좌측 후방 장착·좌측 전방 시야. 좌측면·좌전방 객체 및 근접 장애물.
CAM05: 우측 후방 장착·우측 전방 시야. 우측면·우전방 객체 및 근접 장애물.
CAM06: 후방 중앙 장착·후방 시야. 후방 객체 및 후진 시 근거리 장애물.
공통 객체 인지·진단 인터페이스를 적용한다. 차선·정지선·신호등은 CAM01 우선이며 나머지 채널은 화각·목적에 따라 설정한다. 실제 위치·각도는 현장 확인한다.
2.3 설정 관리
카메라 ID, 설치 위치·시야, 모델명, MX ID, IP, 해상도·FPS·노출·인코딩, Depth 정렬·유효 범위, blob·모델 버전·클래스·임계값, 토픽·Frame ID·QoS, 내부·외부 보정정보를 관리한다.
MX ID 중복 배정을 금지하며, 최종 납품 시 실제 장착 위치와 대조한다.

3. 기능 요구사항 및 확인 방법
3.1 영상 입력·장치 관리
CAM-001: 6대를 서로 다른 ID로 연결한다. 확인: 6대 연결·ID/MX ID 대조.
CAM-002: RGB 해상도·인코딩·기준 시각을 확인할 수 있어야 한다. 확인: 영상·메타데이터 대조.
CAM-003: 거리 산출용 Depth와 영상의 대응 관계를 확인한다. 확인: 시각·프레임·정렬정보 대조.
CAM-004: 채널별 입력·모델·통신 설정을 독립 관리한다. 확인: 설정 파일 대조.
CAM-005: 연결 실패·중단을 채널별 보고한다. 확인: 개별 연결 중단 시험.
3.2 객체 인지
OBJ-001: 차량·보행자를 포함한 확정 클래스를 검출한다. 확인: 대상별 기능시험.
OBJ-002: 클래스·신뢰도·영상 위치를 출력한다. 확인: 영상·메시지 대조.
OBJ-003: 클래스 ID 대응표를 제공한다. 확인: 모델 설명서·설정 대조.
OBJ-004: 무객체 정상 프레임도 빈 결과와 정상 상태를 출력한다. 확인: 무객체 시험.
OBJ-005: 검출 여부와 거리 산출 가능 여부를 구분한다. 확인: Depth 무효 시험.
추가 클래스는 실제 모델·시험 기준으로 확정하며 콘·박스·연석·벽 등은 적용 방법을 명시한다.
3.3 차선·주행가능영역
LAN-001: CAM01 차선·주행가능영역을 산출한다. 확인: 직선·곡선 영상.
LAN-002: 마스크 또는 경계 좌표를 제공한다. 확인: 출력 규격 대조.
LAN-003: 좌우 관측·추정·미검출 상태를 구분한다. 확인: 한쪽·양쪽 미검출.
LAN-004: 연속 프레임의 급격한 위치·형상 변화를 관리한다. 확인: 연속 영상·로그.
LAN-005: 추정·유지 상태와 관측 경과시간을 제공한다. 확인: 일시 미검출.
LAN-006: 유지 허용시간 초과 시 무효로 전환한다. 확인: 장기 미검출.
유지시간·재관측 기준은 설정으로 관리하며 시험에 사용한 값을 기록한다.
3.4 정지선
STP-001: CAM01 정지선을 검출한다. 확인: 정지선 제시 시험.
STP-002: 영상 위치·검출 유효성을 출력한다. 확인: 영상·메시지 대조.
STP-003: 미검출과 기능 비활성을 구분한다. 확인: 미검출·비활성 시험.
정지선 거리를 제공하면 산출 방법·단위·유효 범위·오차 시험을 별도 정의한다.
3.5 신호등·신호색
SIG-001: CAM01 적용 대상 신호등을 검출한다. 확인: 제시 시험.
SIG-002: 위치·점등 색상을 출력한다. 확인: 색상별 영상·메시지 대조.
SIG-003: RED·YELLOW·GREEN·UNKNOWN을 구분한다. 확인: 색상·판정 불가 시험.
SIG-004: 신호등 미검출과 색상 판정 불가를 구분한다. 확인: 미검출·불명확 입력.
화살표·점멸·보행자 신호 및 신호등 형상 지원은 확정 필요.
3.6 거리·연속 프레임
DST-001: RGB 정렬 Depth로 대표 거리를 산출한다. 확인: 정렬 시험.
DST-002: 거리 단위·좌표계를 명시한다. 확인: 메시지·정의서 대조.
DST-003: 무효 Depth·유효 픽셀 부족·범위 이탈은 무효 처리한다. 확인: 예외 입력.
DST-004: 무효 거리를 정상 0m로 해석하지 않게 한다. 확인: 수신 결과.
TMP-001: 카메라 ID·세션·프레임 순번으로 입력을 구분한다. 확인: 로그 연속성.
TMP-002: 재연결·입력 전환 시 추적 이력을 적절히 초기화한다. 확인: 재연결·전환 시험.
TMP-003: 누락·중복·순서 이상을 검출·기록한다. 확인: 송수신 로그 대조.

4. 입력 인터페이스
4.1 RGB
sensor_msgs/msg/Image. 인코딩 bgr8 또는 rgb8은 실제 발행값을 명시한다.
해상도·FPS는 채널별 확정. 좌상단 원점·오른쪽 +u·아래 +v. stamp는 입력 획득 기준 시각, frame_id는 해당 RGB optical 좌표계.
모델 입력과 원본 크기가 다르면 resize·crop·padding 및 검출 좌표 기준을 명시한다.
4.2 Depth·보정정보
Depth: sensor_msgs/msg/Image. 기본안 16UC1·mm·0 무효. RGB 검출 좌표와 정렬한다.
CameraInfo: sensor_msgs/msg/CameraInfo. 크기·내부행렬·왜곡·정류·투영정보 제공.
실제 표현이 다르면 인코딩·단위·무효값을 함께 정의한다. 축소·crop·정렬 영상에 대응하는 보정정보를 제공한다. 유효 거리 범위는 시험 후 확정.
4.3 설정
채널별 접속·MX ID, 영상·Depth, 모델 경로·버전·임계값, 활성 기능·ROI, 거리·추적 파라미터, 토픽·Frame ID·QoS, 통신 이상·재연결 설정을 파일로 관리한다.

5. 출력 데이터 구조
다음은 논리 필드 설계안이며 최종 ROS2 메시지는 별도 정의한다.
5.1 공통
stamp(ROS2 Time): 입력 영상 기준 시각.
frame_id(string): 좌표계. camera_id(string): CAM01~CAM06.
session_id(string): 재기동·재연결 세션. frame_seq(uint64): 세션 내 입력 순번.
model_version/config_version(string): 모델·설정 버전.
status(enum): 정상·비활성·입력 없음·처리 오류 등.
5.2 객체
class_id/class_name, confidence(0~1), bbox(기준 영상 pixel), distance_valid,
position_x/y/z(카메라 optical 좌표·m), distance_method.
Z는 전방축 깊이이며 3차원 직선거리와 구분한다. 직선거리 제공 시 별도 필드·산식 정의.
5.3 차선·주행가능영역
lane_mask, drivable_mask, left_boundary/right_boundary(좌표 또는 곡선),
left_state/right_state(관측·추정·유지·미검출), observation_age_ms, confidence.
마스크 크기·인코딩·값 의미를 명시하며 모델 확률과 후처리 품질값을 구분한다.
5.4 정지선·신호등
정지선: 검출 여부·영상 선분/영역·품질값·유효성.
신호등: 위치·검출 신뢰도·점등 색상·색상 유효성.
복수 검출은 목록으로 출력하며 차량 진행 방향의 적용 대상 선택 여부는 별도 표시한다.
5.5 진단
채널별 연결 상태, 입력·추론·수신 FPS, 송수신·누락·중복 건수, 마지막 정상 시각, 오류 코드, 모델·설정 버전.

6. ROS2 인터페이스 설계안
기존 6채널 후보 체계에 근거한 안이며 기존 설정을 변경하지 않는다.
{cam_id}: cam01~cam06.
/camera/{cam_id}/image_raw : sensor_msgs/msg/Image
/camera/{cam_id}/camera_info : sensor_msgs/msg/CameraInfo
/camera/{cam_id}/depth/image_raw : sensor_msgs/msg/Image
/camera/{cam_id}/depth/camera_info : sensor_msgs/msg/CameraInfo
/perception/{cam_id}/detections : vision_msgs/msg/Detection2DArray
/perception/{cam_id}/result : 사용자 정의 통합 메시지, 확정 필요
/perception/{cam_id}/drivable_area : sensor_msgs/msg/Image
/perception/{cam_id}/lane_line : sensor_msgs/msg/Image
/perception/{cam_id}/debug_image : sensor_msgs/msg/Image
/diagnostics/camera/{cam_id} : diagnostic_msgs/msg/DiagnosticArray
거리·추정 상태·신호색 등은 표준 2D 검출과 별도 통합 결과로 제공하는 방식이다. 최종 필드·패키지명은 메시지·토픽 정의서에서 확정한다.
활성 기능은 정상 무검출 프레임에도 결과를 발행한다. 비활성은 미검출과 구분한다.
영상·마스크·결과는 같은 입력 시각·프레임에 대응한다. 오래된 결과는 원래 stamp와 추정 상태를 보존한다.
QoS의 Reliability·History·Depth 및 큐 포화 정책은 6채널 부하 시험으로 확정한다. 송수신 호환성을 확인한다.

7. 시각 및 좌표계
대응 영상·결과는 입력 영상 기준 stamp를 공유한다. 완료·수신 시각은 별도 기록할 수 있다.
카메라·DCU 시계 대응·오차·동기화 상태를 기록하며 다른 시계 시각을 직접 빼서 지연으로 사용하지 않는다. 6대 하드웨어 동기 촬영 여부는 별도 확인한다.
영상: 좌상단 원점, 오른쪽 +u, 아래 +v, pixel.
Optical: 오른쪽 +X, 아래 +Y, 전방 +Z, m.
차량 좌표계는 통합 정의에 따른다. Frame ID·부모 관계·변환값은 측정·보정 후 확정한다.
Frame ID 출력과 실제 TF 제공을 구분하며 차량 좌표 변환에는 검증된 외부 파라미터를 사용한다.

8. 성능 및 검수 요구사항
기존 검수조서 수정본 기준안이다. 최종 계약·계획서와 대조하여 확정한다.
- 처리속도: 최종 모델 적용 실제 Edge 카메라 6개 채널 각각 평균 8FPS 이상. 추론 완료 건수·시각으로 산출.
- 동시구동: 안정화 후 10분, 수동 재시작 없이 구동.
- 수신율: 같은 구간 채널별 95% 이상. 송신 대비 중복 제외 DCU 수신 건수.
- 객체: 5회 중 4회 이상 종류·위치 및 DCU 수신 성공.
- 차선: 5회 중 4회 이상 좌우 중 1개 이상 위치 및 DCU 수신 성공.
- 정지선: 5회 중 4회 이상 위치 및 DCU 수신 성공.
- 신호등: 5회 중 4회 이상 검출·점등 색상 및 DCU 수신 성공.
- 거리 오차·지연 허용기준 및 측정 구간: 확정 필요.
기본 기능시험 조건은 주간·무강우·무안개·차량 정지·대상 가림 없음이다.
매회 대상 재제시 또는 차량 위치 조정. 5초 관찰 중 올바른 결과 1초 이상 연속 출력·DCU 수신이면 성공.
정상 무검출도 수신율에 포함한다. 표시·추론·수신 FPS를 구분한다.

9. 장애 및 예외 처리
연결 실패: 채널·원인 보고. 통신 중단: 마지막 정상 시각·중단 상태 제공.
